Resposta. A complexidade final depende da representação do grafo e de k; tudo abaixo vale no pior caso sobre grafos com n vértices (e m arestas), com os graus já armazenados durante a construção da representação, como o texto supõe. Com matriz de adjacências, o algoritmo fica em O(n² + k·n log n) para todo k ≥ 0. Para k constante, k ≥ 1, isso é Θ(n²), a mesma classe O(n²) da matriz sem heap: cada vértice retirado ainda custa a leitura de uma linha e uma coluna (2n posições), e o grafo sem arestas força n − k retiradas. Com k = 0 nada é retirado e resta a construção do heap, O(n log n); com k ≥ n o algoritmo para no primeiro teste (|V| < k + 1), em O(1). O heap acelera só a busca do vértice de grau < k, não a classe. Com listas de adjacências, sob as hipóteses H1–H3 do Passo 3, o algoritmo fica em O(m + (k + 1)·n log n), que para k constante é O(m + n log n); para k ≥ 1, essa cota é de classe menor que o O(k n²) do texto sem heap sempre que m ∈ o(n²). Em qualquer das duas representações, a parcela do heap descrita no texto (construção O(n log n) mais as remoções, Σ lg(n − i + 1)) soma O(n log n), e para k constante, k ≥ 1, essa soma de cotas é de ordem exatamente n log n na pior entrada (Σ_{j=k+1}^{n} lg j = lg n! − lg k!). Ela mede só o custo de encontrar e retirar os vértices, não o do algoritmo completo.

INTERPRETAÇÃO.
O enunciado pergunta pela "complexidade final do algoritmo" com o heap "como descrito acima". O algoritmo é o do Subgrafo Induzido Maximal, no passo literal do texto, repetido sobre o grafo atual G com |V| vértices:
    (i) se |V| < k + 1, para: "nenhum vértice pode ter grau ≥ k", e não há subgrafo induzido com a propriedade;
    (ii) senão, se todos os vértices de G têm grau ≥ k, devolve H = G;
    (iii) senão, seleciona um vértice v de grau < k, remove-o de G junto com suas arestas e repete.
O texto supõe que os graus já estão disponíveis: "É razoável supor que, durante a construção de qualquer das duas representações, podemos armazenar em cada vértice, seu grau. Assim, a questão de se determinar se um dado vértice tem grau menor que k se torna uma operação de tempo constante." Adoto essa premissa: os graus iniciais não são calculados pelo algoritmo. O heap tem como chave o grau de cada vértice; o teste (i) usa o contador |V|, o teste (ii) olha a chave mínima do heap, e o passo (iii) retira o mínimo do heap. A resposta tem de incluir tudo o que o algoritmo faz: os testes, a construção do heap, as retiradas, a enumeração dos vizinhos de v e a atualização dos graus deles. O custo das operações do heap (Passos 1 e 2) é uma parcela desse total; os Passos 4 e 5 dão o total em cada representação. Considero k inteiro, k ≥ 0.

QUANTAS RETIRADAS. Seja r o número de vértices retirados. Antes da i-ésima retirada o grafo atual tem n − i + 1 vértices, e o teste (i) exige n − i + 1 ≥ k + 1, isto é, i ≤ n − k. Logo:
    k = 0: o teste (ii) já passa (todo grau é ≥ 0), r = 0;
    k ≥ n: o teste (i) para de saída (n < k + 1), r = 0;
    1 ≤ k ≤ n − 1: r ≤ n − k ≤ n − 1.
Em todos os casos r ≤ n − 1 quando n ≥ 2, e o número de execuções do teste (i), que é r + 1, é ≤ n para todo n ≥ 1.

MODELO DE CUSTO (constantes do texto).
Os custos do texto vêm em notação O sem constantes, então as testemunhas abaixo são dadas em função das constantes dessas cotas, não como números fixos. Sejam:
    b > 0: a construção do heap com n chaves custa no máximo b · n lg n, para n ≥ 2;
    a > 0: a i-ésima remoção do heap custa no máximo a · (1 + lg(n − i + 1));
    g > 0: cada repetição dos testes (i) e (ii), mais a marcação de v como retirado, custa no máximo g.
O "1 +" é necessário: se o argumento for 1 (heap com um só elemento), lg 1 = 0, mas a remoção custa pelo menos uma operação; a leitura literal "custo ≤ a · lg 1 = 0" seria impossível. Com o "1 +", a cota vale para todo i de 1 a n. Uso lg = log₂; a base não altera a classe.

PASSO 1 — PARCELA DO HEAP: CONSTRUÇÃO MAIS REMOÇÕES (COTA SUPERIOR).
Há r ≤ n remoções. Como cada parcela a(1 + lg(n − i + 1)) é ≥ 0, a soma sobre i = 1..r é no máximo a soma sobre i = 1..n:
    Σ_{i=1}^{n} a(1 + lg(n − i + 1)) = a(n + Σ_{j=1}^{n} lg j) = a(n + lg n!),
trocando j = n − i + 1 (quando i vai de 1 a n, j vai de n a 1). Como cada fator de n! = 1 · 2 · … · n é ≤ n, n! ≤ nⁿ e lg n! ≤ n lg n. Para n ≥ 2, lg n ≥ 1, logo n ≤ n lg n. Assim, para todo n ≥ 2,
    custo do heap ≤ b n lg n + a(n + n lg n) ≤ b n lg n + 2a n lg n = (b + 2a) n lg n.
Testemunhas: c = b + 2a, n₀ = 2. Em n = n₀ = 2: n lg n = 2, n = 2 ≤ 2 e lg 2! = 1 ≤ 2; a desigualdade vale. Logo a parcela do heap está em O(n log n) no pior caso sobre grafos com n vértices, para todo k ≥ 0 (a cota não depende de quantos vértices são de fato retirados; com k ≥ n o heap nem chega a ser construído, e a cota continua valendo como cota superior).

PASSO 2 — A SOMA DAS COTAS DO HEAP NÃO PODE SER MELHORADA (k CONSTANTE, k ≥ 1).
Primeiro, lg n! ∈ Θ(n lg n): a cota superior lg n! ≤ n lg n vale para todo n ≥ 1 (Passo 1). Para a inferior, lg n! ≥ Σ_{i=⌈n/2⌉}^{n} lg i, pois as parcelas omitidas lg 1, …, lg(⌈n/2⌉ − 1) são ≥ 0. A soma restante tem n − ⌈n/2⌉ + 1 ≥ n/2 parcelas (n par: n/2 + 1; n ímpar: (n + 1)/2), cada uma ≥ lg⌈n/2⌉ ≥ lg(n/2) ≥ 0 para n ≥ 2. Então lg n! ≥ (n/2) lg(n/2) = (n/2)(lg n − 1), e (n/2)(lg n − 1) ≥ (n/4) lg n equivale a lg n ≥ 2, isto é, n ≥ 4. Em n = n₀ = 4: lg 4! = lg 24 ≈ 4,585 ≥ (4/4) · 2 = 2. Logo lg n! ∈ Θ(n lg n), com c₁ = 1/4, c₂ = 1, n₀ = 4.
Agora a soma das cotas das remoções que de fato ocorrem. Fixe k ≥ 1 e tome o grafo sem arestas com n ≥ k + 1 vértices: todo grau é 0 < k, então o algoritmo retira vértices enquanto |V| ≥ k + 1, ou seja, r = n − k, e para no teste (i) com |V| = k. A i-ésima remoção ocorre com o heap de tamanho n − i + 1, e a soma das cotas é
    Σ_{i=1}^{n−k} a(1 + lg(n − i + 1)) = a((n − k) + Σ_{j=k+1}^{n} lg j) = a((n − k) + lg n! − lg k!).
Para n ≥ 2k + 2 vale n/2 ≥ k + 1, logo ⌈n/2⌉ ≥ k + 1, e a soma Σ_{j=k+1}^{n} lg j contém todas as parcelas Σ_{j=⌈n/2⌉}^{n} lg j usadas acima; então, para n ≥ max(4, 2k + 2), Σ_{j=k+1}^{n} lg j ≥ (n/4) lg n. Em n = n₀ = max(4, 2k + 2) com k = 1 (n₀ = 4): lg 2 + lg 3 + lg 4 = lg 24 ≈ 4,585 ≥ 2. Junto com a cota do Passo 1, a soma das cotas das remoções está em Θ(n log n) nessa família, para cada k ≥ 1 fixo. Com k = 0 ou k ≥ n não há remoção, e a parcela do heap é só a construção (k = 0) ou nada (k ≥ n).
Isso mostra que somar as cotas do texto dá ordem n log n, não menos; não afirma um limite inferior para o tempo real das remoções, porque o texto só fornece cotas superiores. Observação: a cota O(n log n) da construção é a que o texto dá; um heap binário pode ser construído em O(n), mas isso não muda a ordem da parcela do heap quando k ≥ 1 é constante, porque a soma das cotas das remoções já é de ordem n log n na família acima.

PASSO 3 — HIPÓTESES QUE O TEXTO DEIXA IMPLÍCITAS.
H1 (atualização das chaves). Retirar v remove as arestas de v; cada vizinho u de v ainda presente perde 1 de grau, e a chave de u no heap fica desatualizada. Se não for corrigida, o heap pode deixar de devolver um vértice de grau < k que existe. É preciso uma operação de diminuição de chave, que num heap binário custa O(log tamanho) ≤ O(log n), desde que se guarde, para cada vértice, sua posição no vetor do heap (um índice atualizado a cada troca, O(1) extra por troca). Seja d > 0 tal que cada diminuição de chave custa no máximo d(1 + lg n).
H2 (quantas atualizações). No momento da remoção, v tem grau atual < k, ou seja, no máximo k − 1 vizinhos ainda presentes. Logo há no máximo k − 1 diminuições de chave por remoção; com r ≤ n − k remoções (1 ≤ k ≤ n − 1), são no máximo (k − 1)(n − k) ≤ k·n ao todo. Com k = 0 ou k ≥ n não há remoção nem diminuição. Em todos os casos o total D satisfaz D ≤ k·n, e também D ≤ m, pois cada aresta provoca no máximo uma diminuição (quando o primeiro dos seus extremos sai). Este é o mesmo fator (k − 1) que aparece na recorrência da lista de adjacências do texto, T(n) = T(n − 1) + n + (k − 1)(n − 1).
H3 (representação: como achar os vizinhos de v). Matriz: ao retirar v, percorre-se a linha e a coluna de v, como diz o texto, 2n leituras, ignorando os vizinhos já retirados (marca por vértice, O(1)). Listas: percorre-se a lista original de v ignorando os marcados como retirados, sem apagar v das listas dos vizinhos. Cada vértice é retirado no máximo uma vez, então cada lista é percorrida no máximo uma vez: no máximo Σ_v grau(v) = 2m entradas lidas. (Se, em vez de marcar, se apagasse v da lista de cada vizinho percorrendo-a, como na recorrência do texto, então, para k ≥ 2, cada remoção pagaria até (k − 1)(n − 1) e a cota voltaria a O(k n²), sem ganho na cota com o heap. Por exemplo, a estrela K_{1,n−1} com k = 2 e n ≥ 3: as n − 1 folhas têm grau 1 < 2 e o centro tem grau ≥ 2 até restarem 2 vértices, quando o teste (i) para; saem n − 2 folhas. No pior caso sobre a ordem das listas, cada folha retirada está no fim da lista do centro, e apagá-la custa (n − 1) + (n − 2) + … + 2 = n(n − 1)/2 − 1 passos, Θ(n²); com a ordem favorável custaria só n − 2. Com k = 1 o vértice retirado tem grau 0, a parcela de apagar é nula e o ganho permanece.)
Se os graus não estivessem armazenados, calculá-los custaria n² leituras com matriz e O(n + m) com listas; as cotas superiores dos Passos 4 e 5 não mudariam (n² já é parcela da cota da matriz, e n + m ≤ m + n lg n para n ≥ 2), mas o caso k = 0 da matriz passaria a custar n² leituras em vez de só a construção do heap.

PASSO 4 — ALGORITMO COMPLETO, MATRIZ DE ADJACÊNCIAS.
Seja e > 0 tal que ler uma posição da matriz e testar a marca custa no máximo e. Com r retiradas e D diminuições, para n ≥ 2,
    T(n) ≤ g n (testes, r + 1 ≤ n) + b n lg n (construção) + a Σ_{i=1}^{r}(1 + lg(n − i + 1)) (remoções) + e · 2n · r (linha e coluna dos retirados) + d(1 + lg n) · D (H1, H2).
Em forma de recorrência, cada remoção custa O(log n) no heap mais 2n na matriz mais as diminuições de chave: T(n) = T(n − 1) + O(log n) + 2n + (diminuições), sobre a construção do heap. Pelo Passo 1, as duas parcelas do heap somam ≤ (b + 2a) n lg n. Com r ≤ n, a parcela da matriz é ≤ 2e n². Com D ≤ k n e 1 + lg n ≤ 2 lg n (n ≥ 2), a última é ≤ 2d k n lg n. Como n ≤ n lg n ≤ n² para n ≥ 2 (lg n ≥ 1 e lg n ≤ n),
    T(n) ≤ (g + b + 2a + 2e) n² + 2d · k n lg n ≤ C(n² + k n lg n), com C = g + b + 2a + 2e + 2d e n₀ = 2.
Em n = n₀ = 2: n = 2 = n lg n ≤ 4 = n² e 1 + lg 2 = 2 = 2 lg 2; vale. Logo T ∈ O(n² + k n log n) no pior caso sobre grafos de n vértices, para todo k ≥ 0.
k constante, k ≥ 1 (k fixo, independente de n). Cota superior: k n lg n ≤ k n² (pois lg n ≤ n), e T(n) ≤ C(1 + k) n² para n ≥ 2: O(n²), testemunhas c₂ = C(1 + k), n₀ = 2. Cota inferior no pior caso: no grafo sem arestas com n ≥ k + 1, saem r = n − k vértices (Passo 2), cada um com 2n leituras, num total de 2n(n − k) leituras, cada uma custando pelo menos uma operação. Para n ≥ 2k vale n − k ≥ n/2 e 2n(n − k) ≥ n²; em n = n₀ = 2k: 2 · 2k · k = 4k² = n², e 2k ≥ k + 1 porque k ≥ 1. Logo T ∈ Θ(n²) no pior caso, com c₁ = 1, c₂ = C(1 + k), n₀ = 2k (≥ 2). Por exemplo, com k = 1 o grafo sem arestas perde n − 1 vértices e custa 2n(n − 1) leituras. É a mesma classe da matriz sem heap (T(n) = T(n − 1) + n + n do texto, O(n²)): com matriz, percorrer linha e coluna de v já custa 2n por remoção, e o heap não reduz isso. Θ(n²) é afirmação de pior caso: há entradas bem mais baratas (por exemplo, o grafo completo Kₙ com k ≤ n − 1 não perde vértice nenhum).
k = 0. Não há remoção, leitura da matriz nem diminuição; o custo é o teste (i), a construção do heap e o teste (ii): T(n) ≤ 2g + b n lg n ≤ (2g + b) n lg n para n ≥ 2 (pois n lg n ≥ 1; em n = n₀ = 2, n lg n = 2 e 2g ≤ 4g), O(n log n) com c = 2g + b, n₀ = 2, em toda entrada. (Com uma construção em O(n), seria O(n).)
k ≥ n. O teste (i) para de saída: T(n) ≤ g, O(1), em toda entrada, supondo n = |V| disponível (é o tamanho do vetor ou da matriz). Por exemplo, Kₙ com k = n cai aqui: nenhum vértice tem grau ≥ n, e o algoritmo conclui que não há subgrafo sem retirar nada.
k variável. Pela H2, D ≤ (k − 1)(n − k) ≤ (n − 1)²/4 quando 1 ≤ k ≤ n − 1 (o produto de dois números de soma n − 1 é no máximo ((n − 1)/2)²), e D = 0 fora desse intervalo. Logo D ≤ n² e a cota fica O(n² + n² log n) = O(n² log n). Essa cota é maior que o O(n²) sem heap; não afirmo que o custo real chegue a n² log n, porque o texto só dá cotas superiores para as operações do heap.

PASSO 5 — ALGORITMO COMPLETO, LISTAS DE ADJACÊNCIAS.
Seja e > 0 a constante por entrada de lista lida (com o teste da marca). Para n ≥ 2,
    T(n) ≤ g n (testes) + e · 2m (listas dos retirados, H3) + (b + 2a) n lg n (heap, Passo 1) + 2d k n lg n (H1, H2, com 1 + lg n ≤ 2 lg n).
Como n ≤ n lg n para n ≥ 2, T(n) ≤ 2e m + (g + b + 2a) n lg n + 2d k n lg n ≤ C(m + (k + 1) n lg n), com C = 2e + g + b + 2a + 2d e n₀ = 2. Em n = n₀ = 2: n = 2 = n lg n; vale. Logo T ∈ O(m + (k + 1) n log n) no pior caso sobre grafos com n vértices e m arestas, para todo k ≥ 0. O "+ 1" cobre k = 0: mesmo sem nenhuma remoção, a construção do heap custa a parcela n log n. Para k constante (k fixo), k + 1 é constante e T ∈ O(m + n log n), com c = C(k + 1), n₀ = 2. Para k ≥ 1, a cota é melhor que o O(k n²) da lista sem heap sempre que m ∈ o(n²): m + (k + 1) n lg n ≤ m + 2k n lg n, e dividindo por k n² fica ≤ m/n² + 2 lg n / n, que tende a 0; logo a cota está em o(k n²). Com k = 0 nada é retirado e a comparação não se aplica; para grafos densos, m ∈ Θ(n²) e, com k constante, o termo m domina e a cota volta a O(n²). As cotas deste passo são superiores; não afirmo que sejam atingidas.

PASSO 6 — RESUMO.
No pior caso, com os graus armazenados como o texto supõe, o algoritmo completo com o heap custa O(n² + k n log n) com matriz, que é Θ(n²) para k constante, k ≥ 1, O(n log n) para k = 0 e O(1) para k ≥ n; com listas, O(m + (k + 1) n log n) (Passos 4 e 5). A frase do texto, "construção O(n log n) e remoção do i-ésimo elemento O(log(n − i + 1))", soma O(n log n) (Passo 1), e para k constante, k ≥ 1, essa soma de cotas é de ordem exatamente n log n na pior entrada (Passo 2). Essa soma é a parcela do heap, ou seja, o custo de encontrar e retirar os vértices de grau < k. Só seria o custo do algoritmo inteiro se a enumeração dos vizinhos (H3) e as atualizações de grau (H1) fossem desconsideradas; com matriz, a enumeração sozinha já custa 2n por vértice retirado, e o heap não melhora a classe.

Conferência numérica (Python; não faz parte da prova): implementei o algoritmo literal (teste |V| < k + 1, depois o teste do grau mínimo, depois a retirada) com matriz de adjacências, graus pré-armazenados e heap binário com diminuição de chave e vetor de posições. Rodei em todos os 33.867 grafos rotulados com 1 a 6 vértices e em 6.000 grafos aleatórios com 7 e 8 vértices, para cada k de 0 a n + 1. Em todos: o resultado coincide com a força bruta (subconjunto de tamanho máximo com grau induzido ≥ k, ou "nenhum"); o número de leituras da matriz é exatamente 2n·r; r ≤ max(0, n − k), e r = 0 para k = 0 e para k ≥ n (com k ≥ n o heap nem é construído); a i-ésima remoção ocorre com o heap de tamanho n − i + 1; o número de diminuições de chave é ≤ min((k − 1)·r, m). Para cada n ≤ 6 e 1 ≤ k ≤ n − 1, o máximo de leituras sobre todos os grafos é exatamente 2n(n − k), atingido pelo grafo sem arestas (conferido também no grafo sem arestas para n até 39, com 2n(n − k) ≥ n² quando n ≥ 2k), e o máximo de diminuições observado foi (k − 1)(n − k). No Kₙ com k = n (n de 1 a 11) o algoritmo para sem retirar nem ler nada. Com listas de adjacências (20.000 grafos aleatórios com até 9 vértices, listas em ordem aleatória): entradas lidas ≤ 2m e diminuições ≤ min(m, (k − 1)·r). Estrela K_{1,n−1} com k = 2, variante que apaga das listas, n de 3 a 59: saem n − 2 folhas, o centro nunca sai, e o custo de apagar é n(n − 1)/2 − 1 na pior ordem da lista do centro e n − 2 na melhor.
