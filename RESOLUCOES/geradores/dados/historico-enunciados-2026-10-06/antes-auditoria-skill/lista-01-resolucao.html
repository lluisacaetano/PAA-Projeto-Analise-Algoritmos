Questão 1

Enunciado

Responda V para os itens que são verdadeiros e F para os itens que são falsos e justifique suas respostas. Respostas sem justificativas não serão consideradas.

  1. Se eu provar que um algoritmo leva O(n²) no pior caso, é possível que leve O(n) em algumas entradas?
  2. Se eu provar que um algoritmo leva O(n²) no pior caso, é possível que leve O(n) em todas as entradas?
  3. Se eu provar que um algoritmo leva Θ(n²) no pior caso, é possível que leve O(n) em algumas entradas?
  4. Se eu provar que um algoritmo leva Θ(n²) no pior caso, é possível que leve O(n) em todas as entradas?
  5. Se eu provar que um algoritmo leva θ(n²) no pior caso, é possível existir alguma entrada suficientemente grande para a qual o algoritmo realiza pelo menos 100 ∗ n operações primitivas?

Lista revisada pelo professor (o cabeçalho da lista manteve a data original). Em 09/09/2026 o item (e) trocou O(n²) por θ(n²) e entrou um item (f); em 13/09/2026 o professor retirou o item (f). Esta resolução segue a versão de 13/09. As versões anteriores estão arquivadas em listas-de-exercicios/versoes-anteriores/.

Os cinco itens giram em torno de uma única distinção: O é teto e Θ é teto com piso, e ambos falam do máximo W(n), não de cada entrada individual. Por isso custo O(n) em algumas entradas é possível — existe algoritmo em que isso ocorre —, e (a) e (c) são V com ou sem piso: o piso, quando existe, só obriga a entrada que realiza o máximo a ser cara; nada impede outra entrada de custar O(n), e o insertion sort com a entrada já ordenada é uma testemunha (itens (a) e (c) abaixo). Já custo O(n) em todas as entradas é incompatível com um piso de ordem n²: (b) é V porque O não impõe piso nenhum, e (d) é F porque o piso c1n² do Θ obriga alguma entrada a custar pelo menos c1n², o que nenhuma cota c·n acompanha para n grande. O item (e) usa a mesma distinção: é o piso c1n² do θ que obriga alguma entrada grande a passar de 100n.

(a) V

Provar W(n) = O(n²) limita por cima o custo máximo. Nada é dito sobre entradas individuais, que podem custar muito menos que o teto.

Tome o insertion sort, contando comparações de chave. Em toda entrada de tamanho n o algoritmo executa no máximo n(n−1)/2 comparações, logo W(n) ≤ ½n² para todo n ≥ 1: temos W(n) = O(n²) com c = ½ e n0 = 1. Já numa entrada previamente ordenada em ordem crescente, o teste do while falha na primeira avaliação de cada iteração do for, e o custo é exatamente n−1 comparações, isto é, O(n) com c = 1 e n0 = 1.

As duas coisas convivem sem contradição: ½n² é teto de todas as entradas, e as entradas ordenadas ficam bem abaixo dele. Logo, é possível.

(b) V

O ponto aqui é que um teto pode ser folgado. Provar W(n) = O(n²) não afirma que exista entrada custando da ordem de n²; a notação O não impõe piso nenhum.

De fato, custar O(n) em todas as entradas já implica O(n²) no pior caso: se T(x) ≤ c·n para toda entrada x de tamanho n ≥ n0, então W(n) ≤ c·n ≤ c·n² para todo n ≥ máx(n0, 1), pois n ≤ n² quando n ≥ 1.

Exemplo concreto: a busca linear executa no máximo n comparações de chave (com o elemento buscado) em qualquer entrada, logo é O(n) em todas elas (c = 1, n0 = 1) — e também é O(n²) no pior caso. A prova de O(n²) simplesmente não era justa. Logo, é possível.

(c) V

W(n) = Θ(n²) significa que existem c1, c2 > 0 e n0 com c1n² ≤ W(n) ≤ c2n² para todo n ≥ n0. O piso c1n² incide sobre o máximo: ele obriga a existir, para cada n grande, alguma entrada cara. Não obriga que toda entrada seja cara.

Insertion sort de novo, em comparações. No pior caso (vetor estritamente decrescente) a iteração j executa exatamente j−1 comparações de chave: são j avaliações do teste do while, mas a última sai por esgotamento do índice (i = 0) e nem chega a comparar chaves. Somando, Σj=2..n (j−1) = n(n−1)/2. Para n ≥ 2 vale n−1 ≥ n/2, logo W(n) ≥ ¼n²; e sempre W(n) ≤ ½n². Testemunhas: c1 = ¼, c2 = ½, n0 = 2.

Ainda assim, a entrada já ordenada custa n−1 comparações, que é O(n). Logo, é possível.

(d) F

Aqui o quantificador é universal, e ele colide frontalmente com o piso do Θ.

Suponha as duas hipóteses simultaneamente. De W(n) = Θ(n²) vêm c1 > 0 e n1 com W(n) ≥ c1n² para n ≥ n1. De “O(n) em todas as entradas” vêm c > 0 e n2 com T(x) ≤ c·n para toda entrada de tamanho n ≥ n2; como W(n) é o máximo de um conjunto de valores todos limitados por c·n — conjunto finito e não vazio, logo o máximo existe —, segue W(n) ≤ c·n.

Para todo n ≥ n0 = máx(n1, n2):   c1n² ≤ W(n) ≤ c·n  ⟹  c1n² ≤ c·n  ⟹  n ≤ c/c1.

Isto é, todo n ≥ n0 teria de satisfazer n ≤ c/c1, o que é falso: basta tomar n* = máx(n0, ⌊c/c1⌋ + 1), que cumpre n* ≥ n0 mas n* > c/c1. Contradição.

O passo decisivo é W(n) ≤ c·n, e ele só existe porque o limite O(n) foi suposto para todas as entradas. Em (c), onde apenas algumas entradas eram O(n), esse passo não pode ser dado — é exatamente aí que os dois itens se separam.

Logo, é impossível.

(e) V

Duas leituras do enunciado. “Alguma entrada suficientemente grande para a qual realiza pelo menos 100n operações” pode querer dizer (L1) que existe alguma entrada x, de tamanho n qualquer, com T(x) ≥ 100·n; ou (L2) que, para todo n a partir de algum ponto, existe entrada de tamanho n com T(x) ≥ 100·n. (L2) implica (L1). Aqui se prova (L2); por isso a resposta vale em qualquer das leituras.

Suponha W(n) ∈ θ(n²), com testemunhas c1, c2 > 0 e n0 ≥ 1: c1n² ≤ W(n) ≤ c2n² para todo n ≥ n0. Defina

N = máx(n0, ⌊100/c1⌋ + 1).

Para todo n ≥ N: de n ≥ ⌊100/c1⌋ + 1 > 100/c1 vem c1·n > 100 e, multiplicando por n > 0, c1·n² > 100·n; e de n ≥ n0 vem W(n) ≥ c1·n². Encadeando, W(n) > 100·n. Como W(n) é o máximo de T(x) sobre as entradas de tamanho n, ele é atingido por alguma entrada xn, e T(xn) = W(n) > 100·n. (Se se preferir definir W(n) como supremo, o argumento continua: como o supremo passa de 100·n, pela definição de supremo existe x com T(x) > 100·n.)

Portanto, para todo n ≥ N existe uma entrada de tamanho n com mais de 100·n operações — não só “é possível”: é obrigatório. Quem força isso é o piso c1n² do θ. Logo, é possível (e até obrigatório).

Exemplo numérico. Insertion sort, contando só as comparações de chave: no pior caso (vetor em ordem decrescente) são C(n) = n(n−1)/2 comparações, e C(n) ∈ θ(n²) com c1 = ¼, c2 = ½, n0 = 2 (para n ≥ 2, n − 1 ≥ n/2, logo n(n−1)/2 ≥ n²/4; e n(n−1)/2 ≤ n²/2 para todo n ≥ 1). Então N = máx(2, ⌊100/(1/4)⌋ + 1) = máx(2, 401) = 401 e, para n ≥ 401, C(n) ≥ n²/4 > 100n. Como cada comparação é pelo menos uma operação primitiva, o número de operações primitivas da entrada de pior caso também passa de 100n. O limiar N da demonstração é suficiente, não o menor: as comparações da entrada de pior caso já atingem 100n em n = 201, onde 201·200/2 = 20 100 = 100·201.
Fencepost: com N = 400, o elo c1n² > 100n da demonstração falharia, pois (1/4)·400² = 40 000 = 100·400 — embora neste exemplo C(400) = 79 800 ainda passe de 100·400. É o elo genérico que exige o “+1” em ⌊100/c1⌋ + 1.

Sobre a versão original do item (e) e o item (f) retirado. Na versão original da lista, o item (e) dizia “O(n²)” (e não θ(n²)) com “é possível existir”. Aquela versão também era V, mas por outro motivo: um algoritmo que faz exatamente 100n operações em toda entrada é O(n²) (100n ≤ 100n² para n ≥ 1). A versão de 09/09 trazia ainda um item (f), retirado em 13/09, que perguntava se, com O(n²) no pior caso, há obrigatoriamente alguma entrada suficientemente grande com pelo menos 100n operações. A resposta era F — o algoritmo que só devolve A[1] gasta um número constante K de operações, com K < 100; ele é O(n²) e nenhuma entrada chega a 100n. Quem inverte a resposta é a troca de “é possível” por “obrigatoriamente” sob O(n²) (V → F); sob θ(n²) as duas perguntas são V, porque o piso obriga. A resolução completa do (f) está em geradores/dados/lista01/q1ef-limpo.md.

Questão 2

Enunciado

Considere n representando um valor variável e k é um valor constante. Analise os códigos abaixo e encontre a complexidade assintótica em cada caso usando a notação Big O. Dê um limite assintótico tão firme quanto possível. Ao realizar a análise, considere o pior caso. Justifique suas respostas. Respostas sem justificativas não serão consideradas.

Os cinco códigos estão transcritos literalmente, cada um no início do seu item abaixo.

Todo laço for (x = a; x <= b; x = x+1) com m iterações custa 1 (inicialização) + (m+1) testes + m incrementos + m·(custo do corpo), ou seja 2m + 2 + m·corpo. É a regra 4 do guia do enunciado, e é dela que sai tudo abaixo. Atenção ao ponto que mais engana: o custo de um laço inclui os testes de condição, que ocorrem mesmo quando o corpo não executa nenhuma vez.

Código 1  —  O(n²), e o limite é justo: Θ(n²)

Enunciado — código 1 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2for (i = 1; i <= n; i = i + 1)
3{
4    for (j = 1; j <= n; j = j + 1)
5    {
6        soma = soma + 1;
7    }
8}

O laço interno tem n iterações e corpo de custo 1, logo custa 2n + 2 + n = 3n + 2. O laço externo tem n iterações e esse corpo:

T1(n) = 1 + [2n + 2 + n(3n + 2)] = 3n² + 4n + 3.

Como 3n² + 4n + 3 ≤ 10n² para todo n ≥ 1, vale T1(n) = O(n²) com c = 10, n0 = 1; e T1(n) ≥ 3n², logo também Ω(n²). Portanto Θ(n²).

Código 2  —  O(n²), e o limite é justo: Θ(n²)

Enunciado — código 2 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2for (i = 1; i <= n; i = i + 1)
3{
4    for (j = 1; j <= n; j = j + 1)
5    {
6        for (c = j; c <= k; c = c + 1)
7        {
8            soma = soma + 1;
9        }
10    }
11}

Este é o código-armadilha da questão, e ele engana nos dois sentidos.

O laço mais interno quase não contribui. Ele vai de c = j até k, com k constante, logo executa rj = máx(0, k − j + 1) vezes. Como j percorre até n, a partir de j = k+1 ele não executa nenhuma vez. Somando sobre j, para n ≥ k:

K = Σj=1..n rj = k + (k−1) + ⋯ + 1 = k(k+1)/2  — uma constante, independente de n.

Mas o laço do meio continua custando n por iteração de i. Ele é executado n vezes e cada iteração paga o teste da condição e o incremento, tenha ou não trabalho interno. Custo do laço j: 1 + (n+1) + n + Σj(3rj + 2) = 4n + 2 + 3K. Logo

T2(n) = 1 + [2n + 2 + n(4n + 2 + 3K)] = 4n² + (4 + 3K)n + 3,   com K = k(k+1)/2, válido para n ≥ k.

Como K é constante, T2(n) = Θ(n²): o teto sai de T2(n) ≤ (11 + 3K)n² e o piso de T2(n) ≥ 4n², ambos para n ≥ máx(1, k). A constante 11 não é folga gratuita: com c = 7 + 3K a desigualdade falharia em n = 1 sempre que k ≤ 1, pois T2(1) = 11 + 3K > 7 + 3K.

Duas conclusões erradas são comuns aqui. Dizer O(n³) por haver três laços aninhados é frouxo — o enunciado pede o limite mais firme possível, e o terceiro laço só contribui uma constante. E dizer Θ(n), contando apenas as execuções de soma = soma + 1, ignora os n² testes do laço j, que dominam o custo.

Código 3  —  O(n²), e o limite é justo: Θ(n²)

Enunciado — código 3 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2for (i = 1; i <= n; i = i + 1)
3{
4    for (j = 1; j <= i; j = j + 1)
5    {
6        soma = soma + 1;
7    }
8}

O laço interno agora tem i iterações, custando 2i + 2 + i = 3i + 2. Somando sobre o laço externo e usando Σ i = n(n+1)/2:

T3(n) = 1 + [2n + 2 + Σi=1..n(3i + 2)] = 1 + 2n + 2 + 3·n(n+1)/2 + 2n = (3/2)n² + (11/2)n + 3.

Teto: T3(n) ≤ 10n² para n ≥ 1. Piso: T3(n) ≥ (3/2)n². Portanto Θ(n²).

O laço interno é executado em média (n+1)/2 vezes, e não n — o somatório Σ i = n(n+1)/2 é a origem da constante 3/2 em vez de 3. A classe é a mesma do código 1; o que muda é o fator constante.

Código 4  —  O(n²), e o limite é justo: Θ(n²)

Enunciado — código 4 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2for (i= 1; i <= n; i = i + 1)

5    {

7        while ( c <= k )
8        {

11        }

13}

O while é O(1). Ele duplica c a partir de 1 até ultrapassar k, logo executa mk = ⌊lg k⌋ + 1 vezes, supondo k ≥ 1 (para k ≤ 0 o teste falha de saída e o laço não executa, isto é, mk = 0; note que lg k nem está definido aí). Como k é constante, mk é constante: o bloco formado pela atribuição c := 1 seguida do while custa 3mk + 2 = O(1) — o while sozinho custa 3mk + 1, e a unidade restante é a atribuição, que fica fora dele.

O laço j vai de i até n, portanto tem L = n − i + 1 iterações, e Σi=1..n L = n(n+1)/2. Fazendo a conta:

T4(n) = (3mk + 4)·n(n+1)/2 + 4n + 3.

O par de laços forma um triângulo: são n(n+1)/2 pares (i, j), cada um com custo constante.

Testemunhas. De n(n+1)/2 ≥ n²/2 vem o piso T4(n) ≥ ((3mk+4)/2)·n², com c1 = (3mk+4)/2 e n0 = 1. De n(n+1)/2 ≤ n², 4n ≤ 4n² e 3 ≤ 3n² (todas para n ≥ 1) vem o teto T4(n) ≤ (3mk+11)·n², com c2 = 3mk+11 e n0 = 1 — teto justo, com igualdade em n = 1. Portanto Θ(n²), o mesmo do código 3, apenas com constante maior.

Código 5  —  O(n² log n), e o limite é justo: Θ(n² lg n)

Enunciado — código 5 (transcrição literal, com a numeração de linhas da lista)

Aqui está a diferença em relação ao código 4: o while testa contra n, não contra k. Multiplicando por 5 a cada passo, ele executa m(n) = ⌊log5 n⌋ + 1 vezes, que depende de n e vale Θ(log n). Note que a base é irrelevante assintoticamente, pois log5 n = lg n / lg 5.

Os dois laços externos dão n² pares (i, j), cada um pagando o while:

T5(n) = n²·(3m(n) + 4) + 4n + 3 = Θ(n² log n).

Formalmente, de log5 n ≤ m(n) ≤ log5 n + 1 saem o piso T5(n) ≥ (3/lg 5)·n² lg n e o teto T5(n) ≤ 12n² lg n para n ≥ 6.

Questão 3

Enunciado

Demonstre as seguintes propriedades relativas à notação assintótica.

  1. f(n) = 2117,  f(n) ∈ O(1)
  2. f(n) = n² + 2 ∗ n,  f(n) ∈ O(n²)
  3. f(n) = n² − 2 ∗ n + 3,  f(n) ∈ θ(n²)
  4. f(n) = 5 ∗ n,  f(n) ∈ Ω(n)
  5. f(n) = n² + 2 ∗ n − 8,  f(n) ∈ Ω(n²)

As três definições do CLRS, que é o que se deve exibir em cada item:

NotaçãoDefiniçãoO que exibir
O(g(n))∃ c > 0, ∃ n0 > 0 : 0 ≤ f(n) ≤ c·g(n), ∀ n ≥ n0um c e um n0
Ω(g(n))∃ c > 0, ∃ n0 > 0 : 0 ≤ c·g(n) ≤ f(n), ∀ n ≥ n0um c e um n0
Θ(g(n))∃ c1, c2 > 0, ∃ n0 > 0 : 0 ≤ c1·g(n) ≤ f(n) ≤ c2·g(n), ∀ n ≥ n0c1, c2 e n0

Duas exigências que derrubam prova: as constantes são escolhidas antes e não podem depender de n; e a definição exige f(n) ≥ 0 na região n ≥ n0 — o que restringe a escolha de n0 nos itens com termo negativo.

(a) f(n) = 2117 ∈ O(1)

Testemunhas: c = 2117 e n0 = 1.

Para todo n ≥ 1 tem-se 0 ≤ 2117 ≤ 2117·1, com igualdade. A desigualdade não depende de n porque f é constante, então vale trivialmente em toda a região. Qualquer c ≥ 2117 também serve. ∎

O tamanho da constante não importa. 2117 ≈ 1,66·1035 é um número enorme, mas não depende de n; a definição de O só exige que c seja uma constante positiva fixada antes de n, e 2117 é. (Versões anteriores desta resolução liam “2117”: o expoente tinha se perdido na extração do texto do PDF. Corrigido em 06/10/2026.)

(b) f(n) = n² + 2n ∈ O(n²)

Testemunhas: c = 3 e n0 = 1.

Para n ≥ 1 vale n ≤ n², logo 2n ≤ 2n². Somando n² aos dois lados:

0 ≤ n² + 2n ≤ n² + 2n² = 3n²,   para todo n ≥ 1.

A não-negatividade é imediata, pois n² + 2n > 0 para n ≥ 1. ∎

(c) f(n) = n² − 2n + 3 ∈ Θ(n²)

Testemunhas: c1 = 1/2, c2 = 2 e n0 = 1.

Não-negatividade. O discriminante de n² − 2n + 3 é 4 − 12 = −8 < 0 e o coeficiente líder é positivo, logo f(n) > 0 para todo n real. Nenhuma restrição vem daqui.

Limite superior (c2 = 2). Basta n² − 2n + 3 ≤ 2n², isto é, 0 ≤ n² + 2n − 3, ou 0 ≤ (n+3)(n−1), verdadeiro para todo n ≥ 1.

Limite inferior (c1 = 1/2). Basta ½n² ≤ n² − 2n + 3, isto é, 0 ≤ ½n² − 2n + 3, ou 0 ≤ n² − 4n + 6. Esse polinômio tem discriminante 16 − 24 = −8 < 0 e líder positivo, logo é positivo para todo n.

Assim, ½n² ≤ n² − 2n + 3 ≤ 2n² para todo n ≥ 1. ∎

Observe que c2 = 1 não funcionaria com n0 = 1: em n = 1 temos f(1) = 2 > 1 = 1·g(1). Com c2 = 1 seria preciso n0 = 2. A checagem em n = n0 exatamente é o que separa uma prova correta de uma quase-correta.

(d) f(n) = 5n ∈ Ω(n)

Testemunhas: c = 5 e n0 = 1.

Para todo n ≥ 1 vale 0 ≤ 5·n ≤ 5n, com igualdade. Qualquer 0 < c ≤ 5 também serve, pois então c·n ≤ 5n. ∎

(e) f(n) = n² + 2n − 8 ∈ Ω(n²)

Testemunhas: c = 1 e n0 = 4.

É preciso 0 ≤ 1·n² ≤ n² + 2n − 8. A segunda desigualdade equivale a 0 ≤ 2n − 8, isto é, n ≥ 4. A primeira exige f(n) ≥ 0: como f(n) = (n+4)(n−2), isso vale para n ≥ 2, e em particular para n ≥ 4. Logo n² ≤ n² + 2n − 8 para todo n ≥ 4. ∎

Por que n0 = 4 e não menos. Este item é o que mais derruba prova, porque o n0 é justo — não há folga:

Questão 4

Enunciado

Suponha que um algoritmo para um certo problema consome O(n²) unidades de tempo, sendo n o tamanho de uma instância. Meu amigo diz ter outro algoritmo para o mesmo problema que consome apenas Ω(n) unidades de tempo. Devo ficar impressionado(a)?

Não. A afirmação do amigo é quase vazia, e o “apenas” do enunciado é justamente a isca.

Ω é limite inferior. Dizer que um algoritmo consome Ω(n) é dizer que ele gasta pelo menos da ordem de n. Isso não é promessa de eficiência — é o contrário: é uma garantia sobre o quão ruim ele é, no mínimo. Para se impressionar seria preciso um teto (uma afirmação em O) melhor que O(n²), e o amigo não deu nenhum.

A afirmação é compatível com um algoritmo péssimo. Um algoritmo Θ(n5) também é Ω(n), pois n5 ≥ n para n ≥ 1. O mesmo vale para Θ(2n). Ou seja, a frase do amigo não exclui nenhum desses casos.

O que ela de fato informa. Rigorosamente, ela não é totalmente vazia: ela exclui que o algoritmo dele seja sublinear — algoritmos como a busca binária, que é Θ(lg n) e portanto não é Ω(n), ficam de fora. Só que essa é a única informação carregada, e ela é desfavorável a ele: o amigo está dizendo que seu algoritmo não é sublinear.

Cuidado com o argumento tentador “todo algoritmo que lê a entrada inteira já é Ω(n), logo a frase não diz nada”. A implicação vale só nessa direção: ler a entrada inteira ⟹ Ω(n). A recíproca é falsa, e existem problemas que admitem algoritmos sublineares. Por isso a formulação correta é a do parágrafo acima.

Questão 5

Enunciado

Meu algoritmo para um certo problema consome O(n²) unidades de tempo, sendo n o tamanho de uma instância. Meu amigo diz ter outro algoritmo para o mesmo problema que consome O(n ∗ lgn) unidades de tempo. Devo ficar impressionado(a)?

Sim, com ressalvas. Desta vez a comparação é ao menos entre grandezas do mesmo tipo (dois tetos), e n lg n é assintoticamente melhor que n². Mas atenção: das duas afirmações em O, tomadas isoladamente, não se conclui ganho nenhum — é a Ressalva 1 abaixo, e ela é o coração da questão.

O ganho assintótico é real. Vale n lg n = o(n²), e a recíproca falha: n² não é O(n lg n). De fato, suponha por absurdo que existam c > 0 e n0 ≥ 2 (podemos supor n0 ≥ 2, para que lg n > 0) com n² ≤ c·n lg n para n ≥ n0. Dividindo por n lg n > 0:

n / lg n ≤ c, para todo n ≥ n0.

Mas n / lg n é ilimitada: tomando n = 2k temos n / lg n = 2k/k, e como 2k ≥ k² para k ≥ 4, segue 2k/k ≥ k. Basta então escolher k > máx(c, 4) com 2k ≥ n0 para contradizer a desigualdade. ∎

Ressalva 1 — O é teto, dos dois lados. Só posso concluir que há ganho se o meu O(n²) for justo, isto é, se meu algoritmo for de fato Θ(n²). Se minha análise foi frouxa e ele é na verdade Θ(n lg n), as duas garantias declaradas deixam de separar os algoritmos. Note a diferença: nesse caso eu perco a capacidade de concluir o ganho — não que o ganho deixe de existir. Ele pode existir ainda assim (o do amigo pode ser Θ(n)), eu é que não consigo mais afirmá-lo a partir das duas frases.

Ressalva 2 — o teto dele também pode ser folgado. Simetricamente, O(n lg n) não impede que o algoritmo do amigo seja ainda melhor, por exemplo Θ(n). A afirmação dele é um limite superior, não uma descrição exata.

Ressalva 3 — constantes ocultas e o tamanho real de n. A notação assintótica descarta constantes, e elas importam na prática. Se meu algoritmo custa 2n² e o dele 1000·n lg n, o meu é mais rápido até o cruzamento: 2n² ≤ 1000 n lg n equivale a n ≤ 500 lg n, o que vale para 2 ≤ n ≤ 6311. O cruzamento real é n* ≈ 6311,93, de modo que só a partir de n = 6312 o dele passa à frente. Se as instâncias reais forem menores que isso, o ganho assintótico não se converte em ganho prático.

Análise de Algoritmos:

Não há um conjunto de regras para analisar um algoritmo. No entanto, conforme [AHO et al., 1983] podemos seguir o seguinte guia, considerando o modelo computacional Random Access Machine (RAM):

  1. O custo de execução de uma instrução de atribuição, de leitura ou de escrita é O(1);
  2. O custo de execução de uma sequência de instruções é determinado pela instrução de maior custo na sequência de instruções;
  3. O custo de execução de um comando de decisão/seleção é composto pelo custo de execução das instruções no corpo do comando de decisão/seleção mais o custo para avaliar a condição. O custo para avaliar a condição é O(1), e
  4. O custo de execução de um comando de repetição (laço/loop) é a soma do custo de execução do corpo do comando de repetição adicionado ao custo de avaliar a condição de término do comando de execução, multiplicado pelo número de iterações do comando de repetição. O custo para avaliar a condição de término é O(1).

Somatórios e Logaritmos:

  • Σi=1n (i) = n(n + 1)/2
  • Σi=1n (ai) = a(an − 1)/(a − 1)
  • log (a ∗ b) = log a + log b
  • log (a/b) = log a − log b
  • logb a = logc a/ logc b
  • logb ac = c ∗ logb a
  • lg a = log2 a

Hierarquia de funções:

A seguinte hierarquia de funções pode ser definida do ponto de vista assintótico:

1 ≺ log(n) ≺ √n ≺ n ≺ n ∗ log(n) ≺ nc ≺ cn ≺ n! ≺ nn

onde c é uma constante arbitrária inteira ≥ 2.
