Questão 1

Enunciado

Considere as informações abaixo e responda o que se pede. Justifique suas respostas à luz da teoria da complexidade de algoritmos. Questão inspirada em exercícios análogos propostos em [BRASSARD and BRATLEY, 1996].

  1. Considere os algoritmos A e B com funções de complexidade no pior caso, respectivamente, θ(n³) e θ(n²). Em alguns conjuntos de dados, o tempo de execução do algoritmo A é menor que o tempo de execução do algoritmo B, quando testados no mesmo ambiente (mesma arquitetura, mesmo sistema operacional, mesma linguagem de programação e mesmo compilador). Forneça três possíveis explicações para esse fenômeno.
  2. Um pesquisador tem a sua disposição 2 algoritmos para resolver um determinado problema. Um algoritmo possui função de complexidade O(n²) e outro O(n³). Esse pesquisador escolheu o algoritmo com complexidade O(n³). Cite 4 razões que poderiam ter motivado essa opção.
  3. Considere os algoritmos A e B para resolver um determinado problema. O algoritmo A exige 108 ∗ n instruções e o algoritmo B exige 10 ∗ n² instruções. Pode-se afirmar que o algoritmo A é sempre preferível em relação ao algoritmo B?

(a) Três explicações

As três abaixo são mecanismos distintos: a primeira é sobre os fatores constantes, a segunda sobre quais entradas foram testadas, e a terceira sobre o modelo de custo não corresponder à máquina real.

(i) Constantes ocultas e termos de menor ordem. Θ só afirma a existência de constantes, sem fixar seus valores: TA(n) = Θ(n³) significa apenas que existem a1, a2, n0 > 0 com a1n³ ≤ TA(n) ≤ a2n³ para n ≥ n0.

Tome TA(n) = n³ + 10 e TB(n) = 1000n². As duas respeitam as classes dadas, e

TA(n) < TB(n)  ⟺  n³ + 10 < 1000n²,   verdadeiro para todo 1 ≤ n ≤ 999.

Em n = 999: A faz 997 003 009 operações e B faz 998 001 000 — A vence. Em n = 1000 a ordem se inverte (1 000 000 010 contra 1 000 000 000). O cruzamento está em n* ≈ 1000, e ele é determinado pelas constantes, não pelo n0 das definições — que pode perfeitamente valer 1.

(ii) Θ descreve o pior caso, e os dados testados podem não ser o pior caso de A. Aqui o mecanismo é outro: não são as constantes, é a escolha das entradas.

TA(n) = Θ(n³) no pior caso limita o máximo sobre as entradas de tamanho n; não diz nada sobre uma entrada específica. Se A for adaptativo — o quicksort, por exemplo, só degrada para Θ(n²) com pivôs ruins — pode existir uma família de entradas em que o custo efetivo de A seja c·n + O(1). Se, ao mesmo tempo, o conjunto testado for justamente o pior caso de B, cujo custo ali é d·n², então A é mais rápido sempre que

c·n + O(1) < d·n²,  o que vale para todo n suficientemente grande.

Repare que o limiar não é simplesmente n > c/d: com um termo aditivo e > 0, a condição c·n + e < d·n² só vale a partir de n > (c + √(c² + 4de))/(2d). Com c = 3, d = 1, e = 100, isso dá n ≥ 12, e não n > 3. O que importa aqui é só que c·n + O(1) = o(n²), logo existe um ponto a partir do qual A vence.

Não há contradição: as duas afirmações falam de conjuntos de entradas diferentes. Uma cota de pior caso é um teto sobre o máximo, e nada obriga A a gastar n³ nesta família em particular.

(iii) O modelo RAM não captura a hierarquia de memória. O terceiro mecanismo é que o modelo de custo está incompleto para a máquina real.

O modelo RAM cobra O(1) por acesso à memória, independentemente de onde o dado esteja. Na máquina real, um acesso em cache custa da ordem de 1 ns e um acesso à memória principal custa da ordem de 100 ns — duas ordens de grandeza. Um algoritmo Θ(n³) com acesso sequencial (favorável à pré-busca e à localidade de cache) pode executar em menos tempo de parede que um Θ(n²) com acesso aleatório, mesmo realizando mais operações — até o ponto de cruzamento induzido por esse fator.

O ganho é um fator constante, e fator constante não inverte Θ(n³) contra Θ(n²) para todo n. Comparando n³/100 com n², os dois empatam exatamente em n = 100 (10 000 de cada lado) e a partir daí o cúbico volta a perder — em n = 500 já perde por cinco vezes.

As duas classificações continuam corretas: o que falha é a tradução de número de operações para tempo, que o modelo assume proporcional.

(b) Quatro razões

As quatro apoiam-se em eixos independentes: o tamanho das instâncias, a justeza da cota, os fatores constantes, e recursos que não são tempo.

(i) O tamanho das instâncias é limitado pela natureza do problema. Se a aplicação garante n ≤ 100 sempre — por exemplo, um tabuleiro de tamanho fixo, um número de sensores instalados, um grau máximo de polinômio —, o regime assintótico nunca é atingido. A garantia "para todo n ≥ n0" pode simplesmente não se aplicar a nenhuma entrada real. Note que, com n ≤ 100, o custo absoluto dos dois é pequeno (n³ ≤ 10⁶ operações, milissegundos), de modo que a classe assintótica deixa de ser o critério de decisão e os outros passam a decidir. Não é que o cúbico ganhe: com constantes iguais ele perde em todo n ≥ 2 — e em n = 100 perde por um fator 100. O que muda é que perder por 100× algo que leva microssegundos deixa de importar.

(ii) O é apenas teto — a cota O(n³) pode ser frouxa. Este eixo é sobre a qualidade da análise, não do algoritmo. Todo f ∈ O(n²) também está em O(n³), pois n² ≤ n³ para n ≥ 1. Logo O(n³) pode ser apenas a melhor cota que alguém conseguiu provar, enquanto o algoritmo é de fato Θ(n²) ou melhor. Comparar dois algoritmos pelos seus O não é comparação válida: O limita por cima, e um teto frouxo não é evidência de lentidão.

(iii) Os fatores constantes são muito desiguais. Aqui n não é limitado e as cotas são justas; o que decide são as constantes. Com T1(n) = 5000n² e T2(n) = 2n³:

2n³ < 5000n²  ⟺  n < 2500.

Ou seja, o algoritmo cúbico faz menos operações para todo 1 ≤ n ≤ 2499. Em n = 2500 há empate exato (31 250 000 000 operações de cada lado), e só a partir de n = 2501 o quadrático passa à frente. Se a faixa de interesse do pesquisador estiver abaixo de 2500, a escolha do cúbico é a correta.

(iv) Critérios que não são tempo de execução. O modelo RAM contabiliza apenas operações; a decisão de engenharia envolve outros recursos. O algoritmo O(n³) pode usar O(1) de espaço enquanto o O(n²) usa O(n²) e simplesmente não cabe em memória; pode ser muito mais simples de implementar e manter, portanto menos sujeito a erro; pode ser numericamente mais estável; pode já estar implementado, validado e em produção; ou pode ser trivialmente paralelizável, reduzindo o tempo de parede apesar de mais operações totais.

(c) Não

Aqui 108n e 10n² são contagens exatas de instruções, e não cotas assintóticas — então a comparação é direta, sem constantes ocultas.

108·n < 10·n²  ⟺  108 < 10n  ⟺  n > 107   (dividindo por n ≥ 1, que é positivo).

nA = 108nB = 10n²preferível
10610141013B — dez vezes menos instruções
10710151015empate exato
10810161017A

Assintoticamente TA = Θ(n) e TB = Θ(n²), logo A vence para n suficientemente grande. Mas "suficientemente grande" aqui significa n > 107, um limiar altíssimo causado pela constante 108. Como a preferência depende do tamanho da instância, não se pode afirmar que A é sempre preferível.

Questão 2

Enunciado

Considere a teoria da complexidade de algoritmos e responda o que se pede. Justifique formalmente suas respostas. Respostas sem justificativas não serão consideradas.

  1. Explique por que a frase "O tempo de execução do algoritmo A é no mínimo O(n²)"não faz sentido.
  2. Se um algoritmo A tem tempo de execução θ(n²) sobre qualquer entrada de tamanho n, ele pode ter tempo de execução Ω(nlogn) no pior caso?

(a) A frase mistura piso com teto — e, na leitura mais generosa, é vazia

1. Incoerência de sentido. Por definição, T(n) = O(n²) significa que existem c > 0 e n0 > 0 com 0 ≤ T(n) ≤ c·n² para todo n ≥ n0. É um teto: diz que T não passa de c·n². Já "no mínimo" pede uma afirmação da forma T(n) ≥ (algo), que é exatamente o papel de Ω. Não existe, na definição de O, nenhuma desigualdade do tipo T(n) ≥ … para "no mínimo" qualificar.

2. A frase é vazia. Pode-se tentar salvá-la lendo "no mínimo O(n²)" como "T(n) = O(g(n)) para alguma g pelo menos tão grande quanto n²". Mesmo assim não informa nada, porque as classes O são ordenadas por inclusão e crescem para cima:

O(n²) ⊂ O(n³) ⊂ O(2n) ⊂ ⋯

Logo "pelo menos O(n²)" aponta para as classes maiores, que são afirmações mais fracas. Formalmente: seja T o tempo de um algoritmo qualquer e defina g(n) = T(n) + n². Então g(n) ≥ n² para todo n ≥ 1, e vale T(n) = O(g(n)) com c = 1 e n0 = 1, pois 0 ≤ T(n) ≤ T(n) + n² = 1·g(n). Como T era arbitrária, todo algoritmo satisfaz a frase. Uma afirmação satisfeita por todos os objetos do universo não separa nada.

Redação correta: "o tempo de execução de A é Ω(n²)".

(b) Sim, pode — e de fato tem. Não há contradição.

Hipótese. Para toda entrada de tamanho n, o custo de A é Θ(n²): existem c1, c2 > 0 e n0 com 0 ≤ c1n² ≤ T(n) ≤ c2n² para n ≥ n0.

Passo 1 — o pior caso herda os limites. Seja Tpior(n) o máximo de T(x) sobre as entradas de tamanho n. O máximo de valores todos contidos em [c1n², c2n²] também pertence a esse intervalo, logo Tpior(n) = Θ(n²).

Passo 2 — lema: lg n ≤ n para n ≥ 1. Basta 2n ≥ n, por indução. Base: 2¹ = 2 ≥ 1. Passo: se 2n ≥ n com n ≥ 1, então 2n+1 = 2·2n ≥ 2n = n + n ≥ n + 1. Como lg é crescente, n = lg(2n) ≥ lg n.

Passo 3 — testemunhas. Multiplicando o lema por n > 0: n·lg n ≤ n². Tome c = c1 e n0' = máx(n0, 2) (o 2 evita o caso degenerado lg 1 = 0). Para todo n ≥ n0':

Tpior(n) ≥ c1n² ≥ c1·n lg n,   isto é,  Tpior(n) = Ω(n lg n). ∎

Por que não é contraditório. Ω(n lg n) não significa "o algoritmo gasta n lg n". Significa "gasta pelo menos da ordem de n lg n" — e nada impede que gaste muito mais. Como n² domina n lg n, um custo Θ(n²) satisfaz o piso com folga.

A afirmação é verdadeira, mas frouxa. Ela não é a cota inferior mais firme, que é Ω(n²). De fato Tpior não é Θ(n lg n): se fosse, existiria c3 com c1n² ≤ c3·n lg n, ou seja n/lg n ≤ c3/c1 para todo n grande — falso, pois n/lg n é ilimitada (em n = 2k vale 2k/k, que cresce sem limite).

Questão 3

Enunciado

Prove que as sentenças abaixo são verdadeiras ou falsas, usando para isso as definições das notações assintóticas e/ou contra exemplos. Considere que as funções f(n) e g(n) são assintoticamente não negativas.

  1. f(n) ∈ O(g(n)) se e somente se g(n) ∈ Ω(f(n))
  2. Se f(n) ∈ O(g(n)) então g(n) ∈ O(f(n)).
  3. Se f(n) ∈ O(u(n)) e g(n) ∈ O(v(n)) então f(n) + g(n) ∈ O(u(n) + v(n)).
  4. Se f(n) ∈ O(g(n)) e g(n) ∈ O(f(n)) então f(n) ∈ θ(g(n)).

Em provas de propriedade geral as constantes não podem ser apenas declaradas: têm de ser construídas a partir das que a hipótese fornece, e nomeadas sem colisão de símbolos.

(a) Verdadeira

As duas notações são a mesma desigualdade lida dos dois lados. Sendo um "se e somente se", provam-se as duas direções.

(⟹) Se f ∈ O(g), existem c > 0 e n0 com 0 ≤ f(n) ≤ c·g(n) para n ≥ n0. Fixe d = 1/c e m0 = n0 — legítimo porque c > 0 estritamente, e nenhuma delas depende de n. Dividindo por c > 0: d·f(n) ≤ g(n). Com f(n) ≥ 0 e d > 0 vem d·f(n) ≥ 0. Logo 0 ≤ d·f(n) ≤ g(n), que é g ∈ Ω(f).

(⟸) Se g ∈ Ω(f), existem d' > 0 e m0' com 0 ≤ d'·f(n) ≤ g(n). Fixe c' = 1/d' e n0' = m0'. Dividindo por d' > 0: f(n) ≤ c'·g(n); e de 0 ≤ d'·f(n) segue f(n) ≥ 0. Logo f ∈ O(g). ∎

(b) Falsa

Contraexemplo: f(n) = n e g(n) = n², ambas não negativas para n ≥ 1.

A hipótese vale. Com c = 1 e n0 = 1: de n ≥ 1 vem n² ≥ n, logo 0 ≤ n ≤ 1·n² para n ≥ 1, isto é, f ∈ O(g).

A conclusão falha. Suponha por absurdo que existam c > 0 e n0 com 0 ≤ n² ≤ c·n para n ≥ n0. Dividindo por n > 0: n ≤ c para todo n ≥ máx(n0, 1). Tome a testemunha n* = máx(n0, 1) + ⌊c⌋ + 1: ela cumpre n* ≥ máx(n0, 1), então a desigualdade deveria valer, mas n* > c. Contradição. Logo g ∉ O(f). ∎

Coerente com (a): f ∈ O(g) garante apenas g ∈ Ω(f). Nada obriga f a ser também teto de g.

(c) Verdadeira

De f ∈ O(u): existem c1 > 0, n1 com 0 ≤ f(n) ≤ c1u(n) para n ≥ n1. De g ∈ O(v): existem c2 > 0, n2 com 0 ≤ g(n) ≤ c2v(n) para n ≥ n2.

Construa C = máx(c1, c2) e N = máx(n1, n2). Para todo n ≥ N:

f(n) + g(n) ≤ c1u(n) + c2v(n) ≤ C·u(n) + C·v(n) = C·(u(n) + v(n)).

O passo c1u(n) ≤ C·u(n) exige u(n) ≥ 0, garantido pela hipótese de não-negatividade assintótica do enunciado; o mesmo para v. E f(n) + g(n) ≥ 0 porque ambas são não negativas. Logo f + g ∈ O(u + v) com testemunhas C e N. ∎

(d) Verdadeira — é o Teorema 3.1 do CLRS

De f ∈ O(g): existem b > 0, n1 com 0 ≤ f(n) ≤ b·g(n) para n ≥ n1.

De g ∈ O(f): existem a > 0, n2 com 0 ≤ g(n) ≤ a·f(n) para n ≥ n2; dividindo por a > 0, f(n) ≥ (1/a)·g(n).

Construa c1 = 1/a, c2 = b e n0 = máx(n1, n2). Para todo n ≥ n0:

0 ≤ c1·g(n) ≤ f(n) ≤ c2·g(n),

que é exatamente a definição de f ∈ Θ(g). ∎

Note que os símbolos foram batizados a e b justamente para não colidirem com c1 e c2, que são as constantes construídas para o Θ.

Questão 4

Enunciado

Considere n representando um valor variável e k é um valor constante. Analise os códigos abaixo e encontre a complexidade assintótica em cada caso usando a notação Big O. Dê um limite assintótico tão firme quanto possível. Ao realizar a análise, considere o pior caso. Justifique suas respostas. Respostas sem justificativas não serão consideradas.

Os cinco códigos estão transcritos literalmente, cada um no início do seu item abaixo.

Código 1  —  O(log n), e o limite é justo: Θ(log n)

Enunciado — código 1 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2i = 1;
3While ( i <= n )
4{
5    soma = soma + 1;
6    i = i * 10;
7}

Após t multiplicações vale i = 10t (começando em i = 1). O corpo executa enquanto

10t ≤ n  ⟺  t ≤ log10 n,

e como t é inteiro começando em 0, o corpo executa exatamente ⌊log10 n⌋ + 1 vezes. Somando o custo constante de fora do laço e o teste final que falha, T(n) = a + b·(⌊log10 n⌋ + 1) + b.

Teto. Para n ≥ 10 vale log10 n ≥ 1, logo ⌊log10 n⌋ + 1 ≤ 2 log10 n ≤ 2 lg n. Com c = a + 4b e n0 = 10 obtém-se T(n) ≤ c·lg n. Piso. ⌊log10 n⌋ + 1 > lg n / lg 10, logo c1 = b/lg 10 e n0 = 1. Portanto Θ(log n).

Código 2  —  O(log n), e o limite é justo: Θ(log n)

Enunciado — código 2 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2i = n;
3While ( i > 0 )
4{
5    soma = soma + i;
6    i = i / 2; // considere divisao inteira
7}

Com divisão inteira, após t divisões vale i = ⌊n/2t⌋. O corpo executa enquanto ⌊n/2t⌋ ≥ 1, isto é, 2t ≤ n, ou t ≤ lg n. Logo o corpo executa exatamente ⌊lg n⌋ + 1 vezes. Conferência: n = 1 dá 1 iteração; n = 8 dá 4 (i = 8, 4, 2, 1).

Teto. ⌊lg n⌋ + 1 ≤ 2 lg n para n ≥ 2; tome c = a + 3b, n0 = 2. Piso. ⌊lg n⌋ + 1 > lg n; tome c1 = b, n0 = 1. Portanto Θ(log n).

Os códigos 1 e 2 são logarítmicos por mecanismos opostos: no primeiro a variável multiplica por 10 subindo até n; no segundo divide por 2 descendo até 0. As bases são irrelevantes assintoticamente, pois log10 n = lg n / lg 10.

Código 3  —  O(n), e o limite é justo: Θ(n) no pior caso

Enunciado — código 3 (transcrição literal, com a numeração de linhas da lista) 
1x = escolha (1,n); // retorna um valor inteiro no intervalo [1..n] em O (1)
2soma = 0;
3for (i = 1; i <= n; i = i + 1)
4{
5    if ( i != x )
6    {
7        soma = soma + i;
8    }
9    else
10    {
11        for (j = 1; j <= i; j = j + 1)
12        {
13            soma = soma + j * x;
14        }
15    }
16}

A condição é i != x, então o laço interno está no else e só é alcançado quando i == x — o que acontece exatamente uma vez em toda a execução, já que x é um único valor de [1..n].

O laço externo custa a·n + a'. O laço interno roda uma única vez, na iteração i = x, com j = 1..x, custando b·x + b'. Logo

T(n, x) = a·n + b·x + d.

T é crescente em x, e x ∈ [1..n], então o pior caso é x = n: Tpior(n) = (a + b)n + d. Testemunhas: c1 = a, c2 = a + b + d, n0 = 1. Portanto Θ(n).

Por que não é O(n²). O somatório Σi=1..n i = n(n+1)/2, que produziria custo quadrático, só apareceria se o laço interno rodasse para todo i. Aqui ele roda para um único i, e o somatório colapsa num único termo x ≤ n.

Código 4  —  O(n²), e o limite é justo: Θ(n²) no pior caso

Enunciado — código 4 (transcrição literal, com a numeração de linhas da lista) 
1x = escolha (1,n); // retorna um valor inteiro no intervalo [1..n] em O(1)
2soma = 0;;
3for (i = 1; i <= n; i = i + 1)
4{
5    if (i == x)
6    {
7        soma = soma + i;
8    }
9    else
10    {
11        for (j = 1; j <= i; j = j + 1)
12        {
13            soma = soma + j * x;
14        }
15    }
16}

A única diferença em relação ao código 3 é a condição, agora i == x — e ela inverte a análise. O laço interno continua no else, mas agora o else é alcançado para todo i ≠ x, ou seja, em n − 1 das n iterações.

Número total de execuções do corpo interno, em forma fechada:

Σi=1, i≠xn i = n(n+1)/2 − x.

Logo T(n, x) = A·n(n+1)/2 − B·x + C·n + D, que é decrescente em x: cada unidade a mais em x retira exatamente uma passagem pelo laço interno. O pior caso é x = 1. Com n(n+1)/2 ≤ n² para n ≥ 1 obtém-se o teto, e n(n+1)/2 ≥ n²/2 o piso. Portanto Θ(n²).

Os piores casos são opostos: x = n no código 3 e x = 1 no código 4. Responder os dois igual erra um deles.

Código 5  —  O(n log n), e o limite é justo: Θ(n log n)

Enunciado — código 5 (transcrição literal, com a numeração de linhas da lista) 
1soma = 0;
2for (i = 1; i <= n; i = i + 1)
3{
4    for (j = 1; j <= i; j = 3*j)
5    {
6        for (k = 1; k <= 25; k = k + 1)
7        {
8            soma = soma + 1;
9        }
10    }
11}

O laço mais interno é O(1): ele vai de 1 a 25, um limite constante que não depende de n — 25 iterações sempre.

O laço do meio é logarítmico: j multiplica por 3 a cada passo, valendo 3t após t passos. Ele executa enquanto 3t ≤ i, ou seja ⌊log3 i⌋ + 1 vezes.

Somando sobre o laço externo:

T(n) = Θ( Σi=1..n (⌊log3 i⌋ + 1) ) = Θ(n log n).

Teto. ⌊log3 i⌋ + 1 ≤ log3 n + 1 ≤ 2 log3 n para i ≤ n e n ≥ 3; somando sobre n valores, T(n) = O(n log n). Piso. Para os n/2 valores com i > n/2 vale ⌊log3 i⌋ + 1 > log3(n/2), logo T(n) = Ω(n log n). A base 3 só altera a constante, pois log3 n = lg n / lg 3.

Análise de Algoritmos:

Não há um conjunto de regras para analisar um algoritmo. No entanto, conforme [AHO et al., 1983] podemos seguir o seguinte guia, considerando o modelo computacional Random Access Machine (RAM):

  1. O custo de execução de uma instrução de atribuição, de leitura ou de escrita é O(1);
  2. O custo de execução de uma sequência de instruções é determinado pela instrução de maior custo na sequência de instruções;
  3. O custo de execução de um comando de decisão/seleção é composto pelo custo de execução das instruções no corpo do comando de decisão/seleção mais o custo para avaliar a condição. O custo para avaliar a condição é O(1), e
  4. O custo de execução de um comando de repetição (laço/loop) é a soma do custo de execução do corpo do comando de repetição adicionado ao custo de avaliar a condição de término do comando de execução, multiplicado pelo número de iterações do comando de repetição. O custo para avaliar a condição de término é O(1).

Somatórios e Logaritmos:

  • Σi=1n (i) = n(n + 1)/2
  • Σi=1n (ai) = a(an − 1)/(a − 1)
  • log (a ∗ b) = log a + log b
  • log (a/b) = log a − log b
  • logb a = logc a/ logc b
  • logb ac = c ∗ logb a
  • lg a = log2 a

Hierarquia de funções:

A seguinte hierarquia de funções pode ser definida do ponto de vista assintótico:

1 ≺ log(n) ≺ √n ≺ n ≺ n ∗ log(n) ≺ nc ≺ cn ≺ n! ≺ nn

onde c é uma constante arbitrária inteira ≥ 2.
