Questão 1 — máximo por divisão e conquista

Enunciado

"Considere o problema de encontrar o valor máximo em um vetor contendo n números reais. Projete um algoritmo usando o paradigma divisão e conquista para esse problema. Considere que n é um número par. Projete duas abordagens, conforme indicado:
(a) (0.5 ponto) Projete um algoritmo para resolver o problema considerando um subproblema de tamanho n − 1.
(b) (0.5 ponto) Projete um algoritmo para resolver o problema dividindo-o em dois subproblemas de tamanho n/2.
(c) (0.5 ponto) Qual abordagem produz um algoritmo assintoticamente mais eficiente no pior caso? Justifique sua resposta. Respostas sem justificativas não serão consideradas."

Formulário fornecido pela lista (Teorema Mestre, forma de Brassard & Bratley): sejam as constantes naturais a ≥ 1, b ≥ 2 e k ≥ 0; f(n) = c·nk com c > 0 real; T(n) = aT(n/b) + f(n); n potência exata de b; T leva naturais em reais positivos e é assintoticamente não decrescente. Então T(n) ∈ θ(nk) se a < bk; θ(nk·lg n) se a = bk; θ(nlogb a) se a > bk.

0. Convenções

Vetor A[1..n] de reais, n ≥ 1. Custo medido em operações primitivas do modelo RAM (CLRS 3ª ed., §2.2): cada linha executada dos pseudocódigos abaixo, fora o tempo gasto dentro das chamadas recursivas, custa uma constante. Contam-se também, à parte, as comparações entre elementos do vetor, que é a medida usual para este problema.

Custo de uma chamada, fora as chamadas recursivas que ela faz. Cada algoritmo tem as suas próprias constantes — índice a para MaxA, índice b para MaxB; as de um não têm relação com as do outro:
– com tamanho 1 (caso base): uma constante da > 0 (MaxA) ou db > 0 (MaxB);
– com tamanho ≥ 2: depende do ramo tomado na combinação (o ramo "senão" executa uma linha a
mais), mas fica sempre entre duas constantes, 0 < c′a ≤ c″a em MaxA e 0 < c′b ≤ c″b em
MaxB, onde c″ é o custo quando o ramo "senão" é tomado.

Sobre "n é par": os dois algoritmos são escritos para todo n ≥ 1, e precisam ser. Em (a) o subproblema tem tamanho n − 1, que é ímpar; em (b), n par garante apenas que a primeira divisão é exatamente n/2 + n/2 — já com n = 6 os subproblemas têm tamanho 3, que se dividem em 2 + 1. Um algoritmo que só funcionasse para n par não se aplicaria aos próprios subproblemas.

(a) Um subproblema de tamanho n − 1

MaxA(A, n)                  ▷ devolve max{A[1], …, A[n]},  n ≥ 1
1  se n = 1 então devolva A[1]
2  m ← MaxA(A, n − 1)       ▷ conquista: máximo dos n − 1 primeiros
3  se m ≥ A[n] então devolva m
4  senão devolva A[n]       ▷ combina: compara com o último

Chamada inicial: MaxA(A, n).

Correção. P(n): "MaxA(A, n) devolve max{A[1..n]}", para todo n ≥ 1.
Base n = 1: a linha 1 devolve A[1] = max{A[1]}.
H.i.: seja n ≥ 2 e suponha P(n − 1) (note que n − 1 ≥ 1, então P(n − 1) está no domínio). Passo: pela h.i., a linha 2 obtém m = max{A[1..n−1]}; as linhas 3–4 devolvem o maior entre m e A[n], e max{A[1..n]} = max(max{A[1..n−1]}, A[n]). Logo P(n). ∎

Custo. Uma execução de MaxA(A, n) faz n chamadas no total (a inicial e n − 1 recursivas, com tamanhos n, n − 1, …, 1): uma com tamanho 1, de custo da, e n − 1 com tamanho ≥ 2, cada uma de custo entre c′a e c″a. Somando chamada a chamada, toda entrada de tamanho n custa entre da + c′a(n − 1) e da + c″a(n − 1).
(Com um custo constante ca por chamada de tamanho ≥ 2 — ca = c″a no pior caso —, isso é a recorrência Ta(1) = da, Ta(n) = Ta(n − 1) + ca para n ≥ 2, cuja forma fechada é Ta(n) = da + ca·(n − 1): n = 1 dá da ✓; se vale para n − 1, Ta(n) = da + ca(n − 2) + ca = da + ca(n − 1) ✓.)
Pior caso. O vetor estritamente crescente toma o ramo "senão" (linha 4) em todas as n − 1 combinações, pois ali A[n] é maior que todos os anteriores; seu custo é da + c″a(n − 1), que é também a cota superior de qualquer entrada. Portanto o custo de pior caso é exatamente
Tapior(n) = da + c″a·(n − 1).
Θ(n) com c₁ = min(c″a, da), c₂ = c″a + da, n₀ = 1:
– cota inferior: da + c″a(n − 1) ≥ min(c″a,da)·1 + min(c″a,da)·(n − 1) = min(c″a,da)·n;
– cota superior: da + c″a(n − 1) ≤ da·n + c″a·n = (c″a + da)·n, pois n ≥ 1. Em n = n₀ = 1: min(c″a,da) ≤ da ≤ c″a + da ✓. (As mesmas contas com c′a mostram que até o melhor caso é Θ(n).)
(Este algoritmo não é da forma aT(n/b) + f(n): o Teorema Mestre não se aplica; resolve-se por expansão, como acima.)
Comparações entre elementos: Ca(1) = 0 e Ca(n) = Ca(n − 1) + 1, logo Ca(n) = n − 1 — esta contagem não depende dos valores do vetor.
Chamadas (contando a inicial): n. Profundidade da pilha: n.

(b) Dois subproblemas de tamanho n/2

MaxB(A, i, j)                  ▷ devolve max{A[i], …, A[j]},  i ≤ j
1  se i = j então devolva A[i]
2  q ← ⌊(i + j)/2⌋             ▷ divide ao meio
3  esq ← MaxB(A, i, q)         ▷ conquista a metade esquerda
4  dir ← MaxB(A, q + 1, j)     ▷ conquista a metade direita
5  se esq ≥ dir então devolva esq
6  senão devolva dir           ▷ combina

Chamada inicial: MaxB(A, 1, n).

Tamanhos. Seja s = j − i + 1 ≥ 2. A metade esquerda tem q − i + 1 = ⌊(j − i)/2⌋ + 1 = ⌊(s − 1)/2⌋ + 1 = ⌈s/2⌉ elementos; a direita tem s − ⌈s/2⌉ = ⌊s/2⌋. Para s ≥ 2 os dois são ≥ 1 e < s, então a recursão termina. Com s = n par, os dois têm exatamente n/2, como pede o enunciado.

Correção. Indução forte em s. P(s): "MaxB devolve o máximo de qualquer trecho de s elementos", para todo s ≥ 1. Base s = 1: linha 1. H.i.: seja s ≥ 2 e suponha P(t) para todo 1 ≤ t < s. Passo: os tamanhos ⌈s/2⌉ e ⌊s/2⌋ estão em [1, s − 1], então pela h.i. esq = máximo da metade esquerda e dir = máximo da metade direita; o máximo do trecho é o maior dos dois, que as linhas 5–6 devolvem. Logo P(s). ∎

Custo. Primeiro, um fato sobre a recorrência
R(1) = u, R(s) = R(⌈s/2⌉) + R(⌊s/2⌋) + v para s ≥ 2,
com u, v reais quaisquer: sua solução é exata para todo s ≥ 1 (não é preciso supor potência de 2):
R(s) = u·s + v·(s − 1).
Prova por indução forte: s = 1 dá u ✓; para s ≥ 2, pela h.i.,
R(s) = u⌈s/2⌉ + v(⌈s/2⌉ − 1) + u⌊s/2⌋ + v(⌊s/2⌋ − 1) + v = u·s + v(s − 2) + v = u·s + v(s − 1) ✓, usando ⌈s/2⌉ + ⌊s/2⌋ = s (a indução não usa o sinal de u nem de v).
A árvore de chamadas de MaxB depende só de s, não dos valores do vetor. O número de chamadas de tamanho 1 satisfaz R com (u, v) = (1, 0), e o de chamadas de tamanho ≥ 2 satisfaz R com (u, v) = (0, 1): são s e s − 1 (2s − 1 no total). Somando chamada a chamada, toda entrada de tamanho n custa entre db·n + c′b(n − 1) e db·n + c″b(n − 1). Com um custo constante cb por chamada de tamanho ≥ 2 (cb = c″b no pior caso), o custo é Tb(1) = db,
Tb(s) = Tb(⌈s/2⌉) + Tb(⌊s/2⌋) + cb, isto é, R com (u, v) = (db, cb):
Tb(s) = db·s + cb·(s − 1).
Pior caso. No vetor estritamente crescente, em toda combinação o máximo da metade direita é maior que o da esquerda, e o ramo "senão" (linha 6) é tomado em todas as n − 1 combinações; o custo é db·n + c″b(n − 1), a cota superior. Portanto
Tbpior(n) = db·n + c″b·(n − 1).
Θ(n) com c₁ = db, c₂ = c″b + db, n₀ = 1: db·n ≤ db·n + c″b(n − 1) ≤ (c″b + db)·n para n ≥ 1. Em n = 1: db ≤ db ≤ c″b + db ✓.

Confirmação pelo Teorema Mestre (n potência exata de 2, onde a recorrência vira Tb(n) = 2Tb(n/2) + cb = 2Tb(n/2) + cb·n⁰; aqui a, b, k são os parâmetros do formulário, e cb faz o papel do seu c): a = 2, b = 2, k = 0, cb > 0; bk = 2⁰ = 1 < 2 = a, isto é, a > bk — terceira linha do formulário: Tb(n) ∈ Θ(nlog₂ 2) = Θ(n). As hipóteses sobre T valem: Tb(s) = (cb + db)s − cb ≥ db > 0 é positiva e crescente em s. Para n par que não é potência de 2 vale a forma fechada exata acima, que dá a mesma classe.
Comparações entre elementos: Cb(1) = 0, Cb(s) = Cb(⌈s/2⌉) + Cb(⌊s/2⌋) + 1, logo Cb(n) = n − 1 (R com (u, v) = (0, 1)) — também independente dos valores.
Chamadas (contando a inicial): 2n − 1. Profundidade da pilha: 1 + ⌈lg n⌉.

(c) Qual é assintoticamente mais eficiente no pior caso?

Nenhuma das duas. Ambas levam tempo Θ(n) no pior caso:
Tapior(n) = da + c″a(n − 1) ∈ Θ(n) e Tbpior(n) = db·n + c″b(n − 1) ∈ Θ(n), com as testemunhas exibidas em (a) e (b). Como as duas estão em Θ(n), vale Tapior ∈ Θ(Tbpior): nenhuma é assintoticamente melhor. (As constantes de uma e de outra não são comparáveis entre si — cada uma depende das linhas do seu pseudocódigo —, e a pergunta é sobre a classe.) O desvio que depende dos dados (linhas 3–4 em MaxA, 5–6 em MaxB) só altera o custo de cada chamada dentro de uma faixa constante; por isso até o melhor caso de cada uma é Θ(n) — a classe não depende da entrada, só as constantes.

Mais do que isso: as duas fazem exatamente o mesmo número de comparações entre elementos, n − 1, qualquer que seja a entrada. A divisão ao meio não reduz trabalho — ela só organiza o mesmo número de comparações numa árvore balanceada em vez de numa cadeia. Em chamadas (contando a inicial), (b) até faz mais: 2n − 1 contra n — diferença de constante, não de classe.

Por que dividir ao meio não dá lg n aqui. A intuição da busca binária engana: lá há um subproblema de tamanho n/2 (a = 1, T(n) = T(n/2) + Θ(1) ∈ Θ(lg n)); aqui há dois (a = 2). Para n potência de 2, o nível i (0 ≤ i < lg n) da árvore de recursão de MaxB tem 2i chamadas internas, cada uma com uma combinação de custo constante, e o nível lg n tem as n folhas, que não combinam: o número de combinações dobra de um nível para o seguinte enquanto o tamanho cai pela metade, e a soma de 2i para i = 0, …, lg n − 1 dá n − 1 (soma vazia se n = 1). Para n qualquer, a contagem n − 1 vem da recorrência de Cb acima.

Nenhuma abordagem pode ser melhor que Θ(n). Considere qualquer algoritmo determinístico correto que acessa o vetor só lendo posições, ao custo de ao menos uma operação por leitura. Ele precisa ler as n posições: se numa entrada ele nunca lê A[p], troque A[p] por um valor maior que o valor devolvido e que todos os demais elementos; a execução não muda (A[p] não é lido), a saída não muda, e agora está errada. Logo todo algoritmo gasta ao menos 1·n operações para todo n ≥ 1, isto é, Ω(n), e as duas abordagens são ótimas.

A diferença que existe é de espaço, não de tempo: a pilha de recursão tem profundidade n em
(a) e 1 + ⌈lg n⌉ em (b). Com A passado por referência e cada quadro de pilha de tamanho constante, isso é Θ(n) contra Θ(lg n) de memória auxiliar; para o segundo,
lg n ≤ 1 + ⌈lg n⌉ ≤ 2 lg n para todo n ≥ 2 (c₁ = 1, c₂ = 2, n₀ = 2): a cota inferior vale porque ⌈lg n⌉ ≥ lg n; a superior, para n ≥ 4, porque 1 + ⌈lg n⌉ < 2 + lg n ≤ 2 lg n, e em n = 2 e n = 3 por conta direta (2 ≤ 2; 3 ≤ 2 lg 3 ≈ 3,17). n₀ = 1 não serve, pois lg 1 = 0 e a profundidade em n = 1 é 1.

Resposta

(a) MaxA: resolve A[1..n−1] recursivamente e compara o resultado com A[n].
Recorrência Ta(1) = da, Ta(n) = Ta(n−1) + ca; pior caso (vetor estritamente crescente,
ca = c″a): Tapior(n) = da + c″a(n−1) ∈ Θ(n); n − 1 comparações em toda entrada.
(b) MaxB: divide em duas metades (⌈n/2⌉ e ⌊n/2⌋; exatamente n/2 e n/2 na primeira divisão, pois
n é par), resolve cada uma e devolve o maior dos dois resultados.
Tb(n) = 2Tb(n/2) + cb ⇒ Θ(n) pelo Teorema Mestre (n potência de 2; a = 2 > bk = 1,
terceira linha); para todo n, pior caso exatamente Tbpior(n) = db·n + c″b(n−1) ∈ Θ(n);
n − 1 comparações em toda entrada.
(c) Nenhuma é assintoticamente mais eficiente: ambas são Θ(n) no pior caso (e mesmo no melhor),
com exatamente n − 1 comparações; e Θ(n) é ótimo, pois todo algoritmo precisa ler as n
posições. A única diferença assintótica é a profundidade da pilha: Θ(n) em (a), Θ(lg n)
em (b).

Questão 2 — busca num vetor sem fim

Enunciado

"Resolva o seguinte problema:
a) (0.5 ponto) Dado um vetor A [.] de tamanho infinito no qual as primeiras m posições contêm números inteiros em ordem crescente e as demais posições são preenchidas com o valor ∞. Não se conhece o valor de m. Descreva um algoritmo que recebe um valor inteiro x como entrada e encontra uma posição no vetor contendo o valor x, se tal posição existir, em tempo o(n). (Se você não se sente confortável com o fato do vetor ter comprimento infinito, assuma em vez disso comprimento de tamanho n, contudo você não conhece esse comprimento. Assuma, também, que a implementação da estrutura de dados vetor em sua linguagem de programação preferida retorna a mensagem de erro ∞ sempre que elementos A[i] com i > n são acessados).
b) (0.5 ponto) Argumente que seu algoritmo tem a complexidade solicitada."

0. Modelo

Posições 1, 2, 3, …; A[1..m] são inteiros em ordem crescente (o argumento abaixo vale também para ordem não decrescente, com repetições); A[i] = ∞ para i > m; m ≥ 0 é desconhecido. O valor ∞ é tratado como maior que todo inteiro, então a sequência inteira A[1], A[2], … é não decrescente:
(Monotonia) i < i′ ⇒ A[i] ≤ A[i′].
Na versão de comprimento finito n (desconhecido), as posições m < i ≤ n contêm ∞ e o acesso a i > n devolve ∞; o algoritmo enxerga exatamente a mesma sequência que na versão infinita, e m ≤ n.
Custo: cada acesso A[i] e cada operação aritmética ou comparação custa Θ(1) (modelo RAM); conta-se o número de acessos ao vetor, e o tempo é no máximo uma constante vezes esse número.

Tamanho da entrada. Na versão infinita o único parâmetro é m, e o(n) se lê com n = m; na versão finita, n é o comprimento e m ≤ n. Define-se
f(m) = 2⌊lg m⌋ + 3 para m ≥ 1, f(0) = 2.
f é não decrescente em m ≥ 0 (f(0) = 2 < 3 = f(1), e ⌊lg m⌋ não decresce), de modo que f(m) ≤ f(n) em qualquer das leituras, sempre que m ≤ n.

(a) O algoritmo: galope seguido de busca binária

BuscaIlimitada(A, x)
 1  i ← 1
 2  enquanto A[i] < x faça        ▷ fase 1 (galope): testa as posições 1, 2, 4, 8, …
 3      i ← 2·i
 4  lo ← ⌊i/2⌋ + 1;  hi ← i        ▷ se i = 1, então lo = hi = 1
 5  enquanto lo ≤ hi faça          ▷ fase 2: busca binária em A[lo..hi]
 6      meio ← ⌊(lo + hi)/2⌋;  v ← A[meio]
 7      se v = x então devolva meio
 8      se v < x então lo ← meio + 1
 9      senão hi ← meio − 1
10  devolva "x não está no vetor"

A ideia: não se conhece o fim da parte útil, então se procura, dobrando o índice, a primeira potência de 2 cujo conteúdo já é ≥ x. Isso delimita um trecho onde x tem de estar, e nele se faz a busca binária usual. Nenhum passo usa m ou n. Na fase 2 cada volta lê o vetor uma vez (linha 6) e guarda o valor em v.

(b) Correção e complexidade

Lema 1 (a fase 1 termina, e quantas voltas dá). Seja J o número de vezes que o corpo da linha 3 executa. Então i = 2J ao fim da fase 1, e
J = 0 se m = 0; J ≤ ⌊lg m⌋ + 1 se m ≥ 1.
Prova. O teste A[i] < x só é verdadeiro se A[i] é finito, isto é, i ≤ m (pois ∞ < x é falso). Logo, cada vez que o corpo executa, o valor corrente i = 2t satisfaz 2t ≤ m, com t = 0, 1, 2, … em sequência. Se m = 0, A[1] = ∞ e o laço não executa: J = 0. Se m ≥ 1, os valores de t com 2t ≤ m são 0, 1, …, ⌊lg m⌋ — no máximo ⌊lg m⌋ + 1 deles —, e portanto o corpo executa no máximo ⌊lg m⌋ + 1 vezes; em particular a fase 1 sempre termina. ∎

Lema 2 (invariante ao fim da fase 1). Ao fim da fase 1, A[i] ≥ x (o laço parou) e, se J ≥ 1, A[i/2] < x (o teste anterior foi verdadeiro, na posição i/2 = 2J−1).

Lema 3 (x, se existe, está em A[lo..hi]). Se existe p com A[p] = x, então existe uma tal posição em [lo, hi].
Prova. Se A[i] = x, a própria posição i = hi serve. Se A[i] > x, seja p qualquer posição com A[p] = x. Para p ≥ i, a Monotonia daria A[p] ≥ A[i] > x; logo p < i = hi. Se J ≥ 1, para p ≤ i/2 a Monotonia daria A[p] ≤ A[i/2] < x; logo p > i/2, isto é, p ≥ ⌊i/2⌋ + 1 = lo. Se J = 0, lo = 1 ≤ p trivialmente. ∎

Lema 4 (busca binária). Invariante do laço 5–9: "toda posição de [lo₀, hi₀] com valor x está em [lo, hi]", onde [lo₀, hi₀] é o trecho inicial. Vale no início. Se v = A[meio] < x, toda posição p ≤ meio tem A[p] ≤ A[meio] < x, então descartar [lo, meio] preserva o invariante; se v > x, toda posição p ≥ meio tem A[p] > x, e descartar [meio, hi] o preserva. Logo, se o laço termina sem devolver, [lo, hi] ficou vazio e x não ocorre em [lo₀, hi₀] — e, pelo Lema 3, não ocorre no vetor. Reciprocamente, o algoritmo só devolve meio quando A[meio] = x. As posições com ∞ dentro do trecho não atrapalham: ∞ > x, e o trecho continua ordenado.
Número de voltas: se o trecho tem L ≥ 1 posições, após uma volta sem retorno ele tem no máximo ⌊L/2⌋ (a esquerda [lo, meio − 1] tem ⌊(L − 1)/2⌋ ≤ ⌊L/2⌋ posições; a direita [meio + 1, hi] tem ⌈(L − 1)/2⌉ = ⌊L/2⌋). Depois de r voltas, no máximo ⌊L/2r⌋; como uma volta só começa com trecho não vazio, r voltas executadas implicam L/2r−1 ≥ 1, isto é, r ≤ ⌊lg L⌋ + 1. ∎

Correção. Pelos Lemas 3 e 4, o algoritmo devolve uma posição p com A[p] = x quando x ocorre no vetor, e responde que x não está quando não ocorre. ∎

Contagem de acessos — cota superior. Fase 1: J + 1 acessos (J testes verdadeiros e o falso que encerra). Fase 2: o trecho tem L = hi − lo + 1 = i − ⌊i/2⌋ posições, isto é, L = 2J−1 se J ≥ 1 e L = 1 se J = 0; pelo Lema 4, no máximo ⌊lg L⌋ + 1 voltas, com uma leitura por volta (linha 6): no máximo J leituras se J ≥ 1, e 1 leitura se J = 0. Total:
J = 0: no máximo 1 + 1 = 2 acessos;
J ≥ 1: no máximo (J + 1) + J = 2J + 1 ≤ 2(⌊lg m⌋ + 1) + 1 = 2⌊lg m⌋ + 3 (Lema 1). Como J ≥ 1 exige m ≥ 1, conclui-se: para todo m ≥ 0, no máximo f(m) acessos (f(m) = 2⌊lg m⌋ + 3 para m ≥ 1, e f(0) = 2). O tempo total é no máximo K·f(m) para uma constante K > 0 (cada volta de cada laço faz Θ(1) operações além do acesso), isto é, O(lg m) para m ≥ 2. A cota é atingida quando m = 2t − 1 e x > A[m] (conferido por força bruta para m ≤ 699: atingida em m = 1, 3, 7, 15, …, 511).

Contagem de acessos — cota inferior (pior caso). Seja m ≥ 1 e tome x = A[m] + 1 (inteiro, maior que todo elemento finito). Então A[2t] < x para toda posição 2t ≤ m, e o teste da linha 2 é verdadeiro exatamente para t = 0, 1, …, ⌊lg m⌋: J = ⌊lg m⌋ + 1, e só a fase 1 já faz J + 1 = ⌊lg m⌋ + 2 acessos. Logo o pior caso W(m) (máximo de acessos sobre as entradas com esse m) satisfaz
⌊lg m⌋ + 2 ≤ W(m) ≤ 2⌊lg m⌋ + 3 para todo m ≥ 1.
Testemunhas de W ∈ Θ(lg m): c₁ = 1, c₂ = 5, m₀ = 2. A cota inferior vale porque ⌊lg m⌋ + 2 > lg m; a superior, porque 2⌊lg m⌋ + 3 ≤ 2 lg m + 3 lg m = 5 lg m quando lg m ≥ 1, isto é, m ≥ 2. Em m = m₀ = 2: lg 2 = 1, e 1 ≤ W(2) ≤ 5 (de fato W(2) = 4). m₀ = 1 não serve: lg 1 = 0.

Por que isso é o(n). Pela definição (CLRS 3ª ed., §3.1), g(n) ∈ o(n) se para toda constante c > 0 existe n₀ > 0 tal que 0 ≤ g(n) < c·n para todo n ≥ n₀.
Lema 5. 2j ≥ j² para todo inteiro j ≥ 4.
Base j = 4: 16 ≥ 16. Passo: se 2j ≥ j² com j ≥ 4, então 2j+1 = 2·2j ≥ 2j², e
2j² − (j + 1)² = j² − 2j − 1 = (j − 1)² − 2 ≥ 9 − 2 > 0; logo 2j+1 ≥ (j + 1)². ∎
(Falha em j = 3: 8 < 9 — por isso a restrição.)
Consequência: para n ≥ 16, j = ⌊lg n⌋ ≥ 4 e n ≥ 2j ≥ j², donde ⌊lg n⌋ ≤ √n. Então, para n ≥ 16,
f(n) = 2⌊lg n⌋ + 3 ≤ 2√n + 3√n = 5√n (pois √n ≥ 1).
Dado c > 0, tome n₀ = max(16, ⌊25/c²⌋ + 1). Para n ≥ n₀ vale n > 25/c², isto é, √n > 5/c; multiplicando por c·√n > 0: c·n > 5√n ≥ f(n). Então 0 ≤ f(n) < c·n para todo n ≥ n₀, e f ∈ o(n). Para o tempo K·f(n), repita com c/K no lugar de c: n₀ = max(16, ⌊25K²/c²⌋ + 1). Exemplo em n = n₀: c = 1 dá n₀ = 26, f(26) = 11 < 26; c = 1/10 dá n₀ = 2501, f(2501) = 25 < 250,1.
Na versão finita (n ≥ 1), o tempo é ≤ K·f(m) ≤ K·f(n) (f não decrescente, m ≤ n), portanto também o(n).

Por que as alternativas óbvias não servem. A busca linear lê A[1], A[2], … até achar x ou um valor > x; com x > A[m] ela lê m + 1 posições — Θ(m) no pior caso, que não é o(n) (na leitura n = m, ou na versão finita com m = n). A busca binária direta precisa do extremo direito do trecho, que é justamente o que não se conhece. O galope descobre um extremo válido: hi = 2J, com hi ≤ 2m quando J ≥ 1 (pois 2J−1 ≤ m) e hi = 1 quando J = 0 — em no máximo ⌊lg m⌋ + 2 acessos se m ≥ 1, e 1 acesso se m = 0.

Resposta

(a) Galope + busca binária: teste A[1], A[2], A[4], …, A[2t], … até achar a primeira posição
i = 2J com A[i] ≥ x (as posições com ∞ garantem a parada); então faça busca binária em
A[⌊i/2⌋ + 1 .. i], lendo A[meio] uma vez por volta. Devolve uma posição com valor x, ou
"não está".
(b) A fase 1 dá J ≤ ⌊lg m⌋ + 1 dobras (só se dobra enquanto A[i] é finito, isto é, i ≤ m), e a
fase 2 busca num trecho de 2J−1 posições (1 posição se J = 0), com no máximo J leituras
(1 se J = 0). Total: no máximo 2⌊lg m⌋ + 3 acessos para m ≥ 1 (2 para m = 0); como x maior
que todos força ⌊lg m⌋ + 2 acessos, o pior caso é Θ(lg m) (c₁ = 1, c₂ = 5, m₀ = 2), com
m ≤ n. E 2⌊lg n⌋ + 3 < c·n para n ≥ max(16, ⌊25/c²⌋ + 1), qualquer que seja c > 0 — logo o
tempo é o(n).

Questão 3 — qual dos algoritmos A, B, C

Enunciado

"Suponha que, para um problema com entradas de tamanho n, você tenha que escolher um dentre três algoritmos A, B e C. Considere que trata-se do pior caso de cada algoritmo.
1. O algoritmo A resolve problemas dividindo-os em cinco subproblemas de tamanho n/2, recursivamente resolve cada subproblema e então combina as soluções em tempo linear. 2. O algoritmo B resolve problemas de tamanho n, recursivamente resolvendo dois subproblema [sic] de tamanho n − 1 e então combina as soluções em tempo constante.
3. O algoritmo C resolve problemas dividindo-os em nove subproblemas de tamanho n/3, recursivamente resolve cada subproblema e então combina as soluções em tempo θ(n²). Indique qual dos algoritmos é assintoticamente mais eficiente no pior caso. Expresse sua resposta em termos da notação θ. Justifique sua resposta. Resposta sem justificativa não será considerada."

Formulário fornecido pela lista (Teorema Mestre, forma de Brassard & Bratley): sejam as constantes naturais a ≥ 1, b ≥ 2 e k ≥ 0; f(n) = c·nk com c > 0 real; T(n) = aT(n/b) + f(n); n potência exata de b; T leva naturais em reais positivos e é assintoticamente não decrescente. Então T(n) ∈ θ(nk) se a < bk; θ(nk·lg n) se a = bk; θ(nlogb a) se a > bk. A lista também fornece a hierarquia 1 ≺ log n ≺ √n ≺ n ≺ n·log n ≺ nc ≺ cn ≺ n! ≺ nn, "onde c é uma constante arbitrária inteira ≥ 2". Ela não cobre diretamente as comparações desta questão (log₂ 5 não é inteiro, e em nc ≺ cn a base é o mesmo c do expoente); por isso a §5 as prova diretamente.

0. As três recorrências

Casos base: T(1) = t > 0 (qualquer constante positiva). O custo de combinar é positivo:
A: TA(n) = 5·TA(n/2) + fA(n), fA(n) ∈ Θ(n) ("tempo linear")
B: TB(n) = 2·TB(n − 1) + fB(n), fB(n) ∈ Θ(1) ("tempo constante")
C: TC(n) = 9·TC(n/3) + fC(n), fC(n) ∈ Θ(n²)
Primeiro resolve-se cada uma com f exatamente da forma c·nk, c > 0 (a que o teorema exige); depois, na §4, mostra-se que trocar "= c·nk" por "∈ Θ(nk)" não muda a classe.

Hipótese de monotonia (a última do formulário, "T assintoticamente não decrescente"), para quaisquer t, c > 0. Nas potências de b, onde a recorrência define T: T(b·n) = a·T(n) + f(b·n) > T(n), pois a ≥ 1, T(n) > 0 e f(b·n) > 0; e T(1) = t > 0, então por indução T é positiva e crescente sobre as potências de b. Para B, do mesmo modo, TB(n) = 2TB(n − 1) + c > TB(n − 1) > 0. Que o custo não diminua com n a partir de algum N (isto é, T(n) ≤ T(n + 1) para todo n ≥ N) é o que "T assintoticamente não decrescente" significa; o formulário o assume, é natural para tempo de pior caso, e é usado na Observação da §5.

1. Algoritmo A — Teorema Mestre, terceira linha

TA(n) = 5TA(n/2) + c·n: a = 5, b = 2, k = 1, c > 0. bk = 2¹ = 2 e a = 5 > 2: terceira linha do formulário (a > bk). Logo
TA(n) ∈ Θ(nlog₂ 5), com log₂ 5 ≈ 2,3219.
Forma fechada (n = 2m, T(1) = t): TA(n) = (t + 2c/3)·nlog₂ 5 − (2c/3)·n.
Checagem com t = c = 1: TA(n) = (5/3)·nlog₂ 5 − (2/3)·n; TA(2) = 5·1 + 2 = 7 e (5/3)·5 − (2/3)·2 = 25/3 − 4/3 = 7 ✓.
Testemunhas (t, c quaisquer): c₁ = t, c₂ = t + 2c/3, n₀ = 1. A cota superior é imediata; a inferior, (t + 2c/3)nlog₂ 5 − (2c/3)n ≥ t·nlog₂ 5, equivale a (2c/3)(nlog₂ 5 − n) ≥ 0, verdadeira para n ≥ 1 porque log₂ 5 > 1. Com t = c = 1: c₁ = 1, c₂ = 5/3, e em n = n₀ = 1: 1 ≤ 1 ≤ 5/3 ✓.

2. Algoritmo B — fora do Teorema Mestre

A chamada é T(n − 1), não T(n/b): subtrair 1 não é dividir por uma constante b (n − 1 = n/b exigiria b = n/(n − 1), que varia com n). O teorema não se aplica; resolve-se por expansão. Com TB(1) = t e custo de combinação constante fB(n) = c > 0:
TB(n) = 2n−1·t + c·(2n−1 − 1) = 2n−1·(t + c) − c para n ≥ 1.
Prova por indução: n = 1 dá t + c − c = t ✓; se vale para n − 1 (n ≥ 2),
2·[2n−2(t + c) − c] + c = 2n−1(t + c) − c ✓.
Testemunhas: (t/2)·2n = 2n−1·t ≤ TB(n) ≤ 2n−1(t + c) = ((t + c)/2)·2n para n ≥ 1, isto é c₁ = t/2, c₂ = (t + c)/2, n₀ = 1. Com t = c = 1: TB(n) = 2n − 1, c₁ = 1/2, c₂ = 1, e em n = 1: 1 ≤ 1 ≤ 2 ✓. Logo TB(n) ∈ Θ(2n).
(Intuição: a árvore de recursão é binária completa de altura n − 1, com 2n − 1 nós.)

3. Algoritmo C — Teorema Mestre, segunda linha

TC(n) = 9TC(n/3) + c·n²: a = 9, b = 3, k = 2, c > 0. bk = 3² = 9 = a: segunda linha (a = bk). Logo
TC(n) ∈ Θ(n²·lg n).
Forma fechada (n = 3m, T(1) = t): TC(n) = n²·(t + c·log₃ n) — cada um dos m níveis da árvore custa c·9i·(3m−i)² = c·9m = c·n², mais as n² folhas de custo t.
Checagem com t = c = 1: TC(n) = n²(log₃ n + 1); TC(3) = 9 + 9 = 18 = 9·(1 + 1) ✓. Testemunhas (t, c quaisquer): c₁ = c/lg 3, c₂ = (t + c)/lg 3, n₀ = 3. Como log₃ n = lg n / lg 3 e, para n ≥ 3, 1 ≤ lg n / lg 3: (c/lg 3)·n² lg n ≤ n²(t + c log₃ n) ≤ ((t + c)/lg 3)·n² lg n. Com t = c = 1: c₁ = 1/lg 3, c₂ = 2/lg 3; em n = n₀ = 3, n² lg n = 9 lg 3, logo c₁·9 lg 3 = 9 ≤ 18 ≤ 18 = c₂·9 lg 3 ✓ (igualdade na cota superior).
n₀ = 1 não serve: lg 1 = 0 e TC(1) = t > 0.

4. De "= c·nk" para "∈ Θ(nk)"

O enunciado diz "tempo linear", "tempo constante" e "θ(n²)", não exatamente c·nk. Isso não muda nenhuma classe, pelo seguinte lema de comparação.
Lema. Sejam T e T′ definidas pela mesma recorrência (mesmo a, mesma forma de chamada), com o mesmo valor no caso base e com f(n) ≤ f′(n) para todo n. Então T(n) ≤ T′(n) para todo n. Prova: indução sobre n (nas potências de b, ou em n ≥ 1 para B), usando a > 0: T(n) = a·T(·) + f(n) ≤ a·T′(·) + f′(n) = T′(n). ∎
Como f(n) ∈ Θ(nk) e f(n) > 0 para todo n (combinar custa alguma coisa), existem c′, c″ > 0 com c′·nk ≤ f(n) ≤ c″·nk para todo n ≥ 1: para n ≥ n₀ isso é a definição de Θ, e para os finitos n < n₀ basta diminuir c′ e aumentar c″ (f(n)/nk é positivo em cada um deles). Pelo Lema, T fica entre as soluções com f = c′·nk e com f = c″·nk, e as duas estão na mesma classe Θ (§1–§3, cujas formas fechadas e testemunhas valem para quaisquer t, c > 0). Logo TA ∈ Θ(nlog₂ 5), TB ∈ Θ(2n), TC ∈ Θ(n² lg n).

5. Comparação

C é assintoticamente mais eficiente que A. n² lg n / nlog₂ 5 = lg n / nε com ε = log₂ 5 − 2 = log₂(5/4) ≈ 0,3219 > 0. Aplicando L'Hôpital às funções de variável real x > 0 (o limite da sequência é o mesmo),
lim lg x / xε = lim (1/(x ln 2)) / (ε·xε−1) = lim 1/(ε·ln 2·xε) = 0.
Então n² lg n ∈ o(nlog₂ 5): para quaisquer constantes positivas c₂C e c₁A, a partir de algum n vale c₂C·n² lg n < c₁A·nlog₂ 5, e portanto — com as duas cotas valendo no mesmo n, pela Observação abaixo — TC(n) < TA(n).
A é assintoticamente mais eficiente que B. nlog₂ 5 ≤ n³ para n ≥ 1, e n³/2n → 0 (três aplicações de L'Hôpital, de novo em variável real: x³/2x → 3x²/(2x ln 2) → 6x/(2x ln² 2) → 6/(2x ln³ 2) → 0, cada seta significando "tem o mesmo limite que"). Logo nlog₂ 5 ∈ o(2n). Ordem: C ≺ A ≺ B, isto é, Θ(n² lg n) ≺ Θ(nlog₂ 5) ≺ Θ(2n).

Observação — comparar A (definido nas potências de 2) com C (potências de 3) no mesmo n. O teorema é enunciado para n potência exata de b; é a hipótese "T assintoticamente não decrescente" que permite estender a conclusão a todo n. Esboço: se T é não decrescente para n ≥ N e c₁g(bj) ≤ T(bj) ≤ c₂g(bj) para bj ≥ n₀, então para bj ≤ n < bj+1 (com
bj ≥ máx(n₀, N, b)) vale
T(n) ≤ T(bj+1) ≤ c₂g(bj+1) ≤ c₂g(b·n) e T(n) ≥ T(bj) ≥ c₁g(bj) ≥ c₁g(n/b), usando que g é não decrescente para n ≥ 1; para g(n) = ne·lgp n (e > 0, p ≥ 0 — é o caso de nlog₂ 5 e de n² lg n) tem-se g(b·n) ≤ be·2p·g(n) e g(n/b) ≥ g(n)/(be·2p) para n ≥ b², de modo que a classe Θ(g) vale para todo n grande. Com isso, TA e TC são comparáveis no mesmo n.

A vantagem de C é assintótica: para as funções de referência (sem as constantes ocultas, que não se conhecem), a razão lg n / n0,3219 ainda vale ≈ 1,07 em n = 210 e cai para ≈ 0,23 em n = 220.

Resposta

A: T(n) = 5T(n/2) + Θ(n) ⇒ a = 5 > bk = 2 (terceira linha) ⇒ Θ(nlog₂ 5), com
log₂ 5 ≈ 2,32.
B: T(n) = 2T(n − 1) + Θ(1) ⇒ fora do teorema (n − 1 não é n/b); com T(1) = t e custo de
combinação constante c, a expansão dá T(n) = 2n−1(t + c) − c, e pelo lema da §4 qualquer
custo em Θ(1) fica entre duas dessas ⇒ Θ(2n).
C: T(n) = 9T(n/3) + Θ(n²) ⇒ a = 9 = bk = 9 (segunda linha) ⇒ Θ(n² lg n).
O mais eficiente no pior caso é C, com Θ(n² lg n); a ordem é C ≺ A ≺ B, porque n² lg n ∈ o(nlog₂ 5) (log₂ 5 > 2 e lg n ∈ o(nε) para ε > 0) e nlog₂ 5 ∈ o(2n).

Questão 4 — prova por indução

Enunciado

"(1.0 ponto) Prove a assertiva abaixo usando o método da indução matemática.
a) 1/2 + 1/4 + 1/8 + ··· + 1/2n < 1 , ∀n ≥ 1"

Notação

Para cada inteiro n ≥ 1, S(n) = ∑i=1n 1/2i. A escrita 1/2 + 1/4 + 1/8 + … + 1/2n do enunciado é a notação usual para essa soma: só entram os termos com i ≤ n. Para n ≤ 2 a forma com reticências é apenas ilustrativa — vale a definição por ∑: S(1) = 1/2 (um único termo) e S(2) = 1/2 + 1/4 = 3/4.

Por que a indução ingênua (separando o último termo) não fecha

Tentando provar Q(n): S(n) < 1 separando o último termo, o passo seria
S(n+1) = S(n) + 1/2n+1 < 1 + 1/2n+1 — e isso não é < 1. Usando só a informação "S(n) < 1", o passo exigiria a implicação, para todo real s, "se s < 1 então
s + 1/2n+1 < 1", que é falsa (contraexemplo da implicação, não da assertiva: s = 31/32 e n = 3 dão 31/32 + 1/16 = 33/32 ≥ 1). A hipótese "S(n) < 1" perde a informação de quanto falta para 1. Há duas saídas: fortalecer a hipótese (Prova 1) ou separar o primeiro termo em vez do último (Prova 2). As duas são provas completas; basta uma.

Prova 1 — fortalecendo a hipótese

Proposição. Para todo inteiro n ≥ 1, P(n): S(n) = 1 − 1/2n.

Base (n = 1). Lado esquerdo: S(1) = 1/2. Lado direito: 1 − 1/2¹ = 1/2. Iguais: P(1) vale.

Hipótese de indução. Seja n ≥ 1 um inteiro fixado e suponha P(n): S(n) = 1 − 1/2n.

Passo. Separando o último termo da soma até n + 1:
S(n+1) = S(n) + 1/2n+1
= 1 − 1/2n + 1/2n+1 ← h.i. aplicada a S(n)
= 1 − 2/2n+1 + 1/2n+1
= 1 − 1/2n+1,
que é P(n+1). Como P(1) vale e P(n) ⇒ P(n+1) para todo n ≥ 1, pelo princípio da indução P(n) vale para todo n ≥ 1.

Conclusão. Como 2n > 0, tem-se 1/2n > 0 e S(n) = 1 − 1/2n < 1 para todo n ≥ 1. ∎

Prova 2 — a própria assertiva como hipótese de indução, Q(n), separando o primeiro termo

Proposição. Para todo inteiro n ≥ 1, Q(n): S(n) < 1.

Base (n = 1). S(1) = 1/2 < 1.

Hipótese de indução. Seja n ≥ 1 um inteiro fixado e suponha Q(n): S(n) < 1.

Passo. Separando o primeiro termo e pondo 1/2 em evidência no restante:
S(n+1) = 1/2 + ∑i=2n+1 1/2i = 1/2 + ∑j=1n 1/2j+1 = 1/2 + (1/2)·∑j=1n 1/2j
= 1/2 + S(n)/2
< 1/2 + 1/2 = 1 ← h.i.: S(n) < 1, logo S(n)/2 < 1/2 (divide-se por 2 > 0) isto é, Q(n+1). Como Q(1) vale e Q(n) ⇒ Q(n+1) para todo n ≥ 1, pelo princípio da indução Q(n) vale para todo n ≥ 1. ∎
(A troca de índice é j = i − 1, que leva i = 2, …, n+1 em j = 1, …, n; com n = 1 as duas somas têm um único termo, 1/4.)

Conferência

S(1) = 1/2, S(2) = 3/4, S(3) = 7/8 = 1 − 1/8. A identidade S(n) = 1 − 1/2n, a desigualdade S(n) < 1 e a relação S(n+1) = 1/2 + S(n)/2 foram conferidas em aritmética racional exata para n = 1, …, 399.

Resposta

Por indução em n, prova-se a forma mais forte P(n): 1/2 + 1/4 + … + 1/2n = 1 − 1/2n (base: 1/2 = 1/2; passo: 1 − 1/2n + 1/2n+1 = 1 − 1/2n+1); daí a soma é < 1, pois 1/2n > 0. A indução direta em "< 1" separando o último termo não fecha; ela fecha separando o primeiro: S(n+1) = 1/2 + S(n)/2 < 1/2 + 1/2 = 1.

Questão 5 — Teorema Mestre em dez recorrências

(a) T(n) = T(n/3) + 1

Teorema mestre (literal, das "Informações que podem ser úteis"): "Sejam as constantes naturais a ≥ 1, b ≥ 2 e k ≥ 0. Considere a função f(n) da forma c ∗ nk, na qual c > 0 e ∈ R, seja a equação de recorrência dada por T(n) = aT(n/b) + f(n) e suponha n uma potência exata de b. Considere ainda que T é uma função que leva números naturais em números reais positivos e que T é assintoticamente não decrescente, Nessas condições, [BRASSARD and BRATLEY, 1996] indicam que a solução dessa recorrência é limitada assintoticamente por T(n) = θ(nk) se a < bk; θ(nk ∗ lg n) se a = bk; θ(nlogb a) se a > bk."

0. O que o teorema exige — a lista de conferência

Para aplicar esta versão é preciso ter, todas ao mesmo tempo:
(H1) a forma T(n) = a·T(n/b) + f(n) — uma única chamada "dividida por b", repetida a vezes;
(H2) a natural, a ≥ 1;
(H3) b natural, b ≥ 2;
(H4) f(n) = c·nk exatamente, com c > 0 real e k ≥ 0 natural;
(H5) T com valores reais positivos e assintoticamente não decrescente (conferida abaixo nas
potências de b, que é onde a recorrência define T).
Os casos, na ordem em que o formulário os imprime:
1ª linha: a < bk → Θ(nk); 2ª linha: a = bk → Θ(nk lg n); 3ª linha: a > bk → Θ(nlogb a). Nos itens aplicáveis confere-se o resultado com a forma fechada exata (T(1) = 1, n = bm) e exibem-se testemunhas c₁, c₂, n₀ verificadas em n = n₀. Nos itens não aplicáveis dá-se o motivo e, à parte, o que a recorrência realmente faz — o que mostra que a hipótese violada não é detalhe: em (f), (g) e (i), aplicar a fórmula às cegas daria resposta errada qualquer que seja o caso base; em (d), daria resposta errada com o caso base T(1) = 1 do enunciado (e com qualquer T(1) ≤ 4).

(a) T(n) = T(n/3) + 1 — APLICA

a = 1, b = 3, f(n) = 1 = 1·n⁰ ⇒ c = 1 > 0, k = 0. (H1)–(H4) valem.
bk = 3⁰ = 1 = a: 2ª linha ⇒ T(n) ∈ Θ(n⁰·lg n) = Θ(lg n).
Forma fechada (n = 3m, T(1) = 1): T(3m) = m + 1, isto é, T(n) = log₃ n + 1. Positiva e crescente nas potências de 3: (H5) ✓.
Testemunhas: c₁ = 1/lg 3, c₂ = 2/lg 3, n₀ = 3. Com log₃ n = lg n / lg 3 e 1 ≤ lg n / lg 3 para n ≥ 3: (1/lg 3)·lg n ≤ log₃ n + 1 ≤ (2/lg 3)·lg n. Em n = n₀ = 3: 1 ≤ T(3) = 2 ≤ 2 ✓. n₀ = 1 não serve: lg 1 = 0 e T(1) = 1 > c₂·0.

(b) T(n) = 2T(n/2) + n·lg n — NÃO APLICA

a = 2, b = 2 servem, mas f(n) = n lg n não é da forma c·nk (viola H4). Não existem c, k com n lg n = c·nk para todo n potência de 2: n = 2 daria 2 = c·2k e n = 4 daria 8 = c·4k, donde 2k = 4, k = 2 e c = 1/2; mas em n = 8, c·8k = 32 ≠ 24 = 8·lg 8. Nem mesmo "f ∈ Θ(nk)" salvaria: para k ∈ {0, 1}, n lg n / nk ≥ lg n → ∞; para k ≥ 2, n lg n / nk ≤ lg n / n → 0. Então f não está em Θ(nk) para k natural nenhum.
À parte (fora do teorema): por expansão, T(2m) = 2m·(1 + m(m + 1)/2), isto é, T(n) = n·(1 + lg n·(lg n + 1)/2) ∈ Θ(n lg² n) (c₁ = 1/2, c₂ = 2, n₀ = 2; em n = 2: 1 ≤ 4 ≤ 4).

(c) T(n) = T(2n/3) + n — NÃO APLICA

2n/3 = n/(3/2): o "b" seria 3/2, que não é natural nem ≥ 2 (viola H3). Também não há "n potência exata de b" inteira: (3/2)m = 3m/2m, com numerador ímpar e denominador par, não é inteiro para m ≥ 1.
À parte: com piso, T(n) = T(⌊2n/3⌋) + n e T(1) = 1, vale n ≤ T(n) ≤ 3n (soma geométrica de razão 2/3), logo Θ(n) — conferido para n = 1…200 000.

(d) T(n) = 5T(n/4) − n — NÃO APLICA

a = 5, b = 4, mas f(n) = −n = (−1)·n¹: c = −1 < 0 (viola H4). Com o caso base T(1) = 1, (H5) também falha: T(4) = 5 − 4 = 1 e T(16) = 5 − 16 = −11 < 0 — T deixa de ser positiva. À parte: com a recorrência aplicada desde n = 4, T(4m) = (T(1) − 4)·nlog₄ 5 + 4n. A resposta dependeria do caso base: Θ(nlog₄ 5) se T(1) > 4; exatamente 4n se T(1) = 4; negativa a partir de algum n se T(1) < 4. Com a outra opção do enunciado, T(n) = C para n ≤ n0 (chama-se aqui de C a constante do caso base, que o enunciado chama de c, para não confundir com o coeficiente c = −1 de f), o limiar muda: sendo 4m0 a maior potência de 4 que é ≤ n0 (n0 ≥ 1),
T(4m) = ((C − 4·4m0)/5m0)·nlog₄ 5 + 4n para m ≥ m0; o sinal do coeficiente líder é o de C − 4·4m0: positivo dá Θ(nlog₄ 5), zero dá exatamente 4n, negativo faz T ficar negativa (por exemplo, n0 = 4 e C = 10 dão T(4⁶) < 0). Aplicar o teorema às cegas (a = 5 > 4 = bk, 3ª linha) daria Θ(nlog₄ 5) — errado com T(1) = 1, quando T é negativa; só coincidiria com o comportamento real quando T(1) > 4 (ou C > 4·4m0).

(e) T(n) = T(n − 1) + 3 — NÃO APLICA

A chamada é T(n − 1), não T(n/b) (viola H1): n − 1 = n/b exigiria b = n/(n − 1), que varia com n (vale 2 só em n = 2 e fica entre 1 e 2 para n ≥ 3) — não é uma constante. É uma recorrência subtrativa.
À parte: por expansão, T(n) = T(1) + 3(n − 1) = 3n − 2 (com T(1) = 1) ∈ Θ(n); c₁ = 1, c₂ = 3, n₀ = 1 (n ≤ 3n − 2 ⟺ n ≥ 1; em n = 1: 1 ≤ 1 ≤ 3).

(f) T(n) = T(n/3) + 0 — NÃO APLICA

a = 1, b = 3, mas f(n) = 0 não é da forma c·nk com c > 0 (viola H4): 0 = c·nk obriga c = 0. A exigência não é formalidade: aplicando a fórmula com "c = 0, k = 0" (a = 1 = b⁰, 2ª linha) sairia Θ(lg n), que é falso.
À parte: T(3m) = T(1) para todo m — T é constante, Θ(1) (c₁ = c₂ = 1, n₀ = 1, com T(1) = 1).

(g) T(n) = 5T(n/4) − n² — NÃO APLICA

a = 5, b = 4, mas f(n) = −n²: c = −1 < 0 (viola H4). E T não é positiva (viola H5): com T(1) = 1, T(4) = 5 − 16 = −11.
À parte: T(4m) = (T(1) + 16/11)·nlog₄ 5 − (16/11)·n². Como log₄ 5 ≈ 1,161 < 2, o termo −(16/11)n² domina e T fica negativa a partir de algum n qualquer que seja o caso base (com T(1) = 1 já em n = 4; com T(1) = 10⁶, em n = 4¹²); com T(n) = C para n ≤ n0 muda só o coeficiente de nlog₄ 5, e o de n², −16/11, não depende do caso base. Às cegas (a = 5 < 16 = bk, 1ª linha) sairia Θ(n²) — absurdo para uma função que tende a −∞.

(h) T(n) = T(2n/4) + n — APLICA

Simplificando o argumento: 2n/4 = n/2, logo b = 2 (natural ≥ 2). a = 1, f(n) = n = 1·n¹ ⇒ c = 1 > 0, k = 1. (H1)–(H4) valem.
bk = 2¹ = 2 > 1 = a, isto é, a < bk: 1ª linha ⇒ T(n) ∈ Θ(n).
Forma fechada (n = 2m, T(1) = 1): T(n) = 2n − 1 (T(2) = 1 + 2 = 3 ✓). Positiva e crescente: (H5) ✓.
Testemunhas: c₁ = 1, c₂ = 2, n₀ = 1: n ≤ 2n − 1 ⟺ n ≥ 1, e 2n − 1 ≤ 2n. Em n = 1: 1 ≤ 1 ≤ 2 ✓. A armadilha do item: ler "2n/4" e escolher b = 4 (ou a = 2). O valor adequado de b sai do argumento já simplificado.

(i) T(n) = (3/2)·T(n/4) − n² — NÃO APLICA

Lendo "3/2T(n/4)" como (3/2)·T(n/4): a = 3/2 não é natural (viola H2) e c = −1 < 0 (viola H4) — dois motivos independentes. (Na outra leitura, 3/(2·T(n/4)), nem a forma a·T(n/b) + f(n) existe — H1; e em qualquer leitura f(n) = −n² tem c < 0. O veredito não depende da leitura.) E T não é positiva (H5): com T(1) = 1, T(4) = 3/2 − 16 = −29/2.
À parte: T(4m) = (T(1) + 32/29)·(3/2)m − (32/29)·n², negativa a partir de algum n para qualquer caso base, pois (3/2)m = nlog₄(3/2) e log₄(3/2) ≈ 0,29 < 2 (com T(n) = C para n ≤ n0 muda só o coeficiente de (3/2)m; o de n², −32/29, não depende do caso base). Às cegas (a = 3/2 < 16 = bk, 1ª linha) sairia Θ(n²) — absurdo para uma função que tende a −∞.

(j) T(n) = 3T(n/2) + n — APLICA

a = 3, b = 2, f(n) = n = 1·n¹ ⇒ c = 1 > 0, k = 1. (H1)–(H4) valem.
bk = 2 < 3 = a: 3ª linha ⇒ T(n) ∈ Θ(nlog₂ 3), com log₂ 3 ≈ 1,585.

Testemunhas: c₁ = 1, c₂ = 3, n₀ = 1: a cota inferior 3nlog₂ 3 − 2n ≥ nlog₂ 3 equivale a nlog₂ 3 − 1 ≥ 1, verdadeira para n ≥ 1. Em n = 1: 1 ≤ 1 ≤ 3 ✓.

Hierarquia de funções:

A seguinte hierarquia de funções pode ser definida do ponto de vista assintótico:

1 ≺ log(n) ≺ √n ≺ n ≺ n ∗ log(n) ≺ nc ≺ cn ≺ n! ≺ nn

onde c é uma constante arbitrária inteira ≥ 2.

Teorema mestre:

Sejam as constantes naturais a ≥ 1, b ≥ 2 e k ≥ 0. Considere a função f(n) da forma c ∗ nk, na qual c > 0 e ∈ R, seja a equação de recorrência dada por T(n) = aT(n/b) + f(n) e suponha n uma potência exata de b. Considere ainda que T é uma função que leva números naturais em números reais positivos e que T é assintoticamente não decrescente, Nessas condições, [BRASSARD and BRATLEY, 1996] indicam que a solução dessa recorrência é limitada assintoticamente por

T(n) = θ(nk) se a < bk;   θ(nk ∗ lg n) se a = bk;   θ(nlogb a) se a > bk
